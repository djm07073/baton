# Independent cross-review of the transaction-pool reuse report

Research date: 2026-10-04. Reviewed `../pool-wave1/REPORT.md`, its pinned source receipts, current `docs/tx/README.md` and the canonical Rust interfaces. This review writes no implementation, central documentation or adopted policy. Constantinople and Reth/Tempo source conclusions below use their own recorded revisions; they do not establish compatibility with Baton’s native Commonware pin `534af0ede48affd35b2111522527547b4cc9bf72`.

## Assessment

The report’s main conclusion is supported: Constantinople contains a concrete chain pool worth evaluating, while Tempo demonstrates substantial Reth pool/network/builder reuse for an Ethereum-compatible workload. Neither provides an unchanged backend-neutral Baton pool. The report correctly scopes the Commonware inventory absence claim, distinguishes public entry points from private extraction candidates, and preserves the missing native multi-producer, custody and durable-outcome adapters.

Before central documentation adopts the recipes, add an explicit untrusted-ingress validation boundary, retained-selection/cancellation ownership, and exact mined-versus-discarded outcome mapping. A type named `VerifiedTransaction`, an outstanding digest, an actor acknowledgement and an iterator’s `mark_invalid` each have narrower meanings than a generic verified/retained/canonical transaction contract.

## 1. Constantinople: public concrete package, private queue kernel

At Constantinople `3b6c92e76bf582855615844a4175b8304808f6a9`, `TransactionSource` is public but coupled to that chain’s `Header`, `SealedBlock`, transactions and marshal `Update`; its proposal method takes parent, round and already-filled signed-transaction bytes. The public webserver mailbox/channel, actor and config permit whole-package wiring. The queue lane, entry, admission, packing and outcome helpers reside privately in `webserver/actor.rs`. This supports “reuse the concrete package where compatible; otherwise extract/adapt the implementation with provenance.” It does not support calling the proposed generic extraction an already exposed Commonware pool primitive. [Public source contract](https://github.com/commonwarexyz/constantinople/blob/3b6c92e76bf582855615844a4175b8304808f6a9/crates/mempool/src/lib.rs#L9-L35), [mailbox entry points](https://github.com/commonwarexyz/constantinople/blob/3b6c92e76bf582855615844a4175b8304808f6a9/crates/mempool/src/webserver/mailbox.rs#L102-L173), [private packing helpers](https://github.com/commonwarexyz/constantinople/blob/3b6c92e76bf582855615844a4175b8304808f6a9/crates/mempool/src/webserver/actor.rs#L402-L457).

The report already identifies the different Commonware dependency revision and concrete sender/recipient/value/nonce model. Preserve these conditions when presenting the fit spike. Generic parameters over crypto/context are not generic transaction semantics. Do not silently adopt its foreground priority, FIFO whole-batch selection, grace timeout or transfer state rules. [Concrete transaction model](https://github.com/commonwarexyz/constantinople/blob/3b6c92e76bf582855615844a4175b8304808f6a9/crates/primitives/src/transaction.rs#L134-L164).

### Required correction: ingress verification is outside the actor

`VerifiedTransaction<H>` is exactly a type alias for `SignedTransaction<H>`; its documentation says the caller accepted the signature. `SignedTransaction::new_unchecked` is public. `message_digest()` returns the stored sealed transaction digest. This type does not prove that arbitrary caller-created values were cryptographically checked. [Alias, unchecked constructor and stored digest](https://github.com/commonwarexyz/constantinople/blob/3b6c92e76bf582855615844a4175b8304808f6a9/crates/primitives/src/transaction.rs#L41-L74).

Public `Mailbox::try_submit` separately accepts a caller-supplied digest vector and transaction vector. The actor’s `new_transactions` merely inserts each transaction’s `message_digest()` in `known_digests`. Its submit handler registers the caller-supplied digests with status watchers, without checking vector correspondence there. A direct P2P adapter must verify the selected encoding/signature domain and exact signed subject, derive validated transaction/status identities and align the watcher vector before admission. It must not grant trusted status to bytes merely by constructing the aliased type. [Caller-supplied identities](https://github.com/commonwarexyz/constantinople/blob/3b6c92e76bf582855615844a4175b8304808f6a9/crates/mempool/src/webserver/mailbox.rs#L112-L139), [dedup without verification](https://github.com/commonwarexyz/constantinople/blob/3b6c92e76bf582855615844a4175b8304808f6a9/crates/mempool/src/webserver/actor.rs#L559-L574), [watcher identities](https://github.com/commonwarexyz/constantinople/blob/3b6c92e76bf582855615844a4175b8304808f6a9/crates/mempool/src/webserver/actor.rs#L767-L796).

The existing HTTP path performs request/count/encoded-byte limits, bounded verification-work admission, configured decoding and signature-chunk verification, then derives the digest vector from validated transactions. Bypassing HTTP must retain equivalent applicable gates using the chosen Baton schema. This does not select Baton’s presently open message-versus-envelope transaction identity. [Actual HTTP validation and identity derivation](https://github.com/commonwarexyz/constantinople/blob/3b6c92e76bf582855615844a4175b8304808f6a9/crates/mempool/src/webserver/http.rs#L246-L332). HTTP source was additionally read from the pinned raw URL during this cross-review; the other anchors are present in the report’s query receipts.

### Selection, cancellation and finalization timing

The report correctly flags destructive pop: `pop_lane_proposal` removes the queue entry and decrements queued bytes before returning transactions. Its `ProposedBatch` retains only height and digests. Keeping a digest pending does not retain transaction bytes for cancellation or reselection. The actor calls `response.send_lossy` after popping; the inspected branch has no prior response-closed check or reinsertion on unsuccessful delivery. Before exposing this as Baton selection, choose an explicit reservation/retained-entry or retained-body/reference adapter that survives caller cancellation and local proposal failure. No such adapter was implemented or tested here. [Pop and outstanding representation](https://github.com/commonwarexyz/constantinople/blob/3b6c92e76bf582855615844a4175b8304808f6a9/crates/mempool/src/webserver/actor.rs#L420-L434), [lossy response after selection](https://github.com/commonwarexyz/constantinople/blob/3b6c92e76bf582855615844a4175b8304808f6a9/crates/mempool/src/webserver/actor.rs#L829-L842).

Queue capacity checks sum foreground/background queued bytes; outstanding popped bodies, digest/status/watchers and any added custody/reservation store need their own coordinated bounds. Do not describe `max_pool_bytes` as an aggregate budget for all retained transaction material. [Queue budget](https://github.com/commonwarexyz/constantinople/blob/3b6c92e76bf582855615844a4175b8304808f6a9/crates/mempool/src/webserver/actor.rs#L596-L623).

The marshal `Update::Block` path intersects finalized body digests with local outstanding proposals, expires unmatched entries by height/grace and acknowledges the update after its local bookkeeping. If no proposals are outstanding it skips transaction extraction and acknowledges immediately. This is neither an Executor durability barrier nor a general removal of queued entries mined by another producer. The report is correct to feed Baton’s canonical maintenance from durable Executor outcomes and keep local `on_proposal` distinct. Do not map native producer acceptance, retirement or a body-service acknowledgement to `on_commit`. [Finalized-body handler](https://github.com/commonwarexyz/constantinople/blob/3b6c92e76bf582855615844a4175b8304808f6a9/crates/mempool/src/webserver/actor.rs#L844-L894), [grace/outstanding resolution](https://github.com/commonwarexyz/constantinople/blob/3b6c92e76bf582855615844a4175b8304808f6a9/crates/mempool/src/webserver/actor.rs#L461-L518).

Public `try_submit` waits for a terminal batch status; internal `try_ingest` returns admission status. The proposed early-admission bridge is needed: waiting for terminal finalization in `TxPool::admit` would conflate ingress and canonical lifecycle. Existing status/outcome retention is not a restart-persistent Baton custody guarantee. [Completion meanings and visibility](https://github.com/commonwarexyz/constantinople/blob/3b6c92e76bf582855615844a4175b8304808f6a9/crates/mempool/src/webserver/mailbox.rs#L108-L173).

## 2. Reth assembly and Tempo extensions

Tempo `61c979a524f9af5de9c540a0088c429a44741e4c` assembles a Reth validator/task executor, provider/EVM configuration, standard pool and maintenance, then adds Tempo transaction validation, ordering and a separate 2D-nonce pool. Its network builder starts the Reth network with the pool; its optional extra RLPx subprotocol carries finalization certificates. Reth’s transactions manager implements announcements, fetching, per-peer seen state, import and propagation. The report accurately assigns the complete tx transport path to Reth rather than Tempo certificate gossip. [Node pool assembly](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/node/src/node.rs#L772-L856), [network assembly](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/node/src/node.rs#L205-L226), [Reth manager](https://github.com/paradigmxyz/reth/blob/038edab20dfff017f7a7502e683c732e5628ad89/crates/net/network/src/transactions/mod.rs#L271-L321).

Reth `038edab20dfff017f7a7502e683c732e5628ad89` explicitly requires Ethereum nonce/gas/fee information and `EthPoolTransaction`, with Alloy and Ethereum consensus/pooled forms. Base Reth-first reuse is a reasonable conditional EVM recipe. Tempo extensions should remain conditional on an explicit workload decision; AMM, payment budgets, keychain and nonce lanes are not generic Baton requirements. No reviewed source establishes this Reth assembly’s Native Multimmit exact-context integration. [Reth assumptions](https://github.com/paradigmxyz/reth/blob/038edab20dfff017f7a7502e683c732e5628ad89/crates/transaction-pool/src/lib.rs#L136-L161), [transaction bounds](https://github.com/paradigmxyz/reth/blob/038edab20dfff017f7a7502e683c732e5628ad89/crates/transaction-pool/src/traits.rs#L1340-L1350).

### Required correction: mined is different from discarded

Reth `TransactionPool::remove_transactions` explicitly removes entries as discarded, not mined. Recipe B may list this API as a reuse surface, but the durable canonical-success adapter must use the suitable canonical/mined maintenance path or specify an intentional mapping. Blindly calling `remove_transactions` for every successful Executor outcome changes backend event semantics. Tempo maintenance processes provider canonical Commit/Reorg notifications and post-state; that notification contract does not by itself prove Baton’s covering durability. Adapt the canonical event feed only after Baton’s durable outcome condition and preserve irrevocable order instead of inheriting reorg semantics. [Discarded removal contract](https://github.com/paradigmxyz/reth/blob/038edab20dfff017f7a7502e683c732e5628ad89/crates/transaction-pool/src/traits.rs#L496-L504), [Tempo post-state maintenance](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/transaction-pool/src/maintain.rs#L475-L548).

`best_transactions_with_attributes` yields a block-production iterator; `BestTransactions::mark_invalid` controls subsequent iterator dependency exclusion. Tempo uses it when gas/encoded-block capacity is insufficient as well as for execution failures. These operations must not be translated into permanent TxPool retirement or durable canonical failure. The report’s packing discussion is correct, but central recipes should state the narrower lifecycle meaning. [Iterator and removal APIs](https://github.com/paradigmxyz/reth/blob/038edab20dfff017f7a7502e683c732e5628ad89/crates/transaction-pool/src/traits.rs#L396-L410), [iterator invalidation contract](https://github.com/paradigmxyz/reth/blob/038edab20dfff017f7a7502e683c732e5628ad89/crates/transaction-pool/src/traits.rs#L1117-L1123), [capacity exclusion](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/payload/builder/src/lib.rs#L573-L630).

## 3. Byte selection and static analysis

Constantinople’s `filled` budget counts encoded signed transactions; the caller reserves body framing. Selection stops at an oversized front batch and preserves whole batches. Tempo accounts for full RLP block size and chain-specific gas classes in an execution-aware builder. Preserve the distinction between payload-selection allowance, complete encoded-body limit and custody/storage budgets. None proves that Baton may silently omit or reorder committed occurrences; BlockService must commit the exact selected body and Executor must consume exact authenticated order. [Source byte contract](https://github.com/commonwarexyz/constantinople/blob/3b6c92e76bf582855615844a4175b8304808f6a9/crates/mempool/src/lib.rs#L17-L33), [whole-batch packing](https://github.com/commonwarexyz/constantinople/blob/3b6c92e76bf582855615844a4175b8304808f6a9/crates/mempool/src/webserver/actor.rs#L402-L457).

Tempo’s additional stateless hook accepts origin and pooled transaction and returns validation success/failure. It does not return Baton features or a classification decision, nor establish placement/cache-version rules. It is a useful integration analogue for a payload-only admission check. The stateful hook additionally receives `AccountInfoReader`; placing that into Baton’s static analysis would contradict the current contract. Reth’s broader admission can be backend-state-dependent, but it must remain distinct from Baton’s pure `analyze/classify`. [Exact hook signatures](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/node/src/node.rs#L678-L719).

## Adoption conditions and preserved decisions

The following details are necessary before using the report as an implementation recipe:

1. Explicit bounded untrusted-ingress validation and recomputed status/transaction identity alignment before direct mailbox use.
2. Retained bytes/reservations and cancellation/reselection ownership for destructive Constantinople selection; coordinated outstanding-material limits.
3. An exact durable Executor outcome adapter distinguishing mined, discarded, failed, replayed and local candidate expiration as applicable to the chosen backend.
4. Separate static feature/classification semantics from upstream validation hooks and stateful builder filtering.
5. A compatibility check for the chosen package and dependency graph, plus native producer context versus canonical execution parent binding.

These are interface/lifecycle gaps, not reasons to replace working queue, crypto, transport or packing internals with duplicate Baton engines. Router versus packing-filter placement, backend/identity/duplicate policy, persistence, limits and cancellation cells remain undecided. Bank semantics remain outside scope. The review ran no protocol tests or compatibility spike and makes no adoption claim.
