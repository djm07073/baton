# Wave 6 — native evidence reuse and the smallest Orderer handoff

**Reuse native retained certificates and their verifier/codec, plus Commonware's existing storage/resolver primitives. Do not add a second generic ProofArchive/HistoryResolver engine.** The missing connection is a recoverable export of the native owner's exact selected source and interpretation. Merely exposing its current checkpoint or journal cannot supply that connection: those stores recover native safety, not a complete history of external ordered delivery.

This is a source/API audit, not an implementation, executed recovery trace, dependency compatibility test, or closure of Baton proof obligations. Canonical baseline: `8b61492`; inspected primary Commonware commit: `534af0ede48affd35b2111522527547b4cc9bf72`. All 37 freshly retrieved files match Git blob identities in three freshly retrieved complete pinned trees. `source-manifest.json` binds bytes, paths and hashes; the two guessed resolver paths returning 404 are recorded separately. No callable Commonware MCP tool was exposed in this subagent runtime; no new MCP result is claimed. Indexed v2026.9.0 remains a separately labeled corroborating reference, not native graph compatibility evidence.

## What native persistence really retains

| Existing owner/store | Actual retained material | Boundary for an external Orderer |
|---|---|---|
| SafetyJournal | Contiguous `DomainEvent` changes with barrier/generation/cursor identity; local signed/constructed artifacts, durable outbox, highest DA certificates, selected forwarded view exits, and L-QC signing-floor transitions | Not every authenticated remote artifact or every direct-pool source revision. The epoch safety suffix is compacted, not an append-only external witness archive |
| CheckpointStore | Latest acknowledged Snapshot in existing Metadata's atomic two-blob storage | Latest recovery base; no historical snapshot lookup API, full external ordered-range log or application delivery cursor |
| Snapshot's DurableState | Local artifacts, signing floor/proposal anchor, outbox/reservations, selected forwarded V-QCs/nullifications/exits, DA/signing/view obligations | Full `FinalityState`/`DirectPool` source-selection history is absent; ordering envelope payload is currently empty |
| Native view resolver | Volatile, bounded semantic view-proof custody, reseeded from selected durable artifacts after recovery | Serves nullification, V-QC or covering L-QC; not arbitrary original artifact/history lookup |

These statements follow the complete [Change enum](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/machine/durability.rs#L1189), [DurableState and retained-artifact projection](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/machine/durability.rs#L1584), [empty ordering snapshot payload](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/machine/durability.rs#L1970), and [CheckpointStore](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/storage/checkpoint.rs#L1).

The distinction matters before a portable L-QC exists. Native authenticated raw-vote pools are independent of V-QC selection; reaching `n-f` produces local finality immediately, while L-QC assembly is asynchronous. Thus waiting for an eventual L-QC or replacing the exact selected pool with an arbitrary verifying quorum is not an unchanged export recipe. [Native pool/finality boundary](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/machine/finality.rs#L1).

Restoration constructs a fresh FinalityState, restores DurableState and selected safety/DA/view context, then silently replays the safety suffix. Replay explicitly clears newly-ready admissions rather than reporting them externally. Some retained authenticated artifacts can reconstruct current claims, but this does not reconstruct all previous arrival/source-selection revisions or redeliver previously emitted exact ranges. [Fresh versus restored machine](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/machine/state.rs#L680), [silent replay](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/machine/reducer.rs#L1306).

Native compaction removes old whole journal sections behind a durable checkpoint, including during restart after recovered body custody has been verified. View-history retirement uses the native current-view retention floor and drops older local/forwarded/exit references. Neither path consults Executor's durable application receipt. A later covering checkpoint or L-QC cannot be assumed to preserve an external witness required for an already emitted range. [Recovery compaction](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/engine.rs#L175), [native view compaction](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/machine/reducer.rs#L3840).

## What can be called or encoded unchanged

- `Running::serve(view)` returns `Option<ViewProof>`. Use it for matching retained native view evidence. It can return an L-QC above the requested view, and enqueue failure/stopping/non-retention returns `None`; neither result provides exact historic artifact lookup or proof of an empty slot. Resolver retention replaces same-view representatives, keeps the greatest L-QC floor, and prunes covered exits. [Public serve](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/engine.rs#L568), [resolver custody and covering lookup](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/actors/resolver/actor.rs#L223).
- Public `ViewProof` has existing typed variant codecs under native `CodecConfig`. Public `TipRecord` has a bounded one-tip-per-chain codec and commitment function. Keep those bytes/types where they match the exported material. A leader/certificate commitment is not the complete opening chain; validators reconstruct the TipRecord from the authenticated parent V-QC. [ViewProof codec](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/machine/emission.rs#L17), [TipRecord](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/types/history.rs#L10).
- Existing `Scheme::certificate_verifier` and typed certificate verification methods avoid a second general verifier. Trusted epoch/namespace/committee and actual parent/history/policy bindings remain application input. Certificate-only construction does not supply the sharing material needed for raw DA/nullification shares. [Certificate verifier](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/scheme/bls12381_threshold.rs#L293), [batch verification](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/scheme/bls12381_threshold.rs#L889).
- `Running::inspect`/cloneable `Inspector` provides a normalized diagnostic snapshot through a fallible bounded query. It is not a resumable event stream or lossless witness handoff. [Inspector](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/engine.rs#L529).

`machine` and native `storage` are crate-private. Snapshot, Change, DomainEvent, SafetyJournal, CheckpointStore and JournalRecord are not application reexports. Their internal public methods/codecs do not make them callable application APIs. The voter journal command surface has append/roll/prune, with one affine owner; it has no external read/subscription command. A narrow owner facade is required to expose retained material, rather than reopening the same live safety partition through a second owner. [Visibility/reexports](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/mod.rs#L223), [journal commands](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/actors/voter/journal.rs#L687), [internal event codec](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/machine/durability/codec.rs#L152).

Resolver availability also does not prove fsync completion: one staged retention path runs after the journal accepts append admission, before the barrier completion. Another runs at acknowledged completion, and recovery reseeds retained proofs. Preserve those distinct conditions when handing material to an external durable owner. Do not label all served objects physically durable merely because native comments call them “durably admitted.” [Staged retention](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/actors/voter/executor.rs#L602), [acknowledged retention](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/actors/voter/executor.rs#L121), [recovery reseed](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/actors/voter/actor.rs#L2358).

## Minimum connection to develop — no additional generic engine

1. **Expose the existing owner's exact selected source transition.** Bind the native-selected signed artifact or aggregate certificate/opening, exact context and immutable interpretation to the export. Existing FinalityFact/evidence hashes/inspection are projections, not verification material. The export may reference existing retained immutable bytes when their identity, provenance and recovery coverage are actually guaranteed. It must carry or retain missing source/opening material when the safety store does not retain it. Public certificate verification does not recreate crate-private tip extraction or the unproved direction-preserving proposal bridge.
2. **Make that handoff recoverable before relying on it for external delivery.** The native safety event vocabulary does not already journal this complete source transition. A narrow amendment on the native owner or a connected durable export record using existing Journal/Archive/Metadata is required; placement/format is still open. Cover export interruption, retirement/compaction and restart without reinterpreting an accepted source. Adding public reads alone is insufficient. This audit does not establish how lossless bounded export preserves native liveness; that integration obligation remains open and must not become a report/direction/Executor approval round.
3. **Use one coherent evidence owner and existing generic fetch/storage machinery.** Resolve exact missing material through the existing generic resolver's Producer/Consumer connection and verify its binding before use. Reuse supported typed codecs and Archive lookup/gap APIs; choose only the narrow identity/retention connection. A native view lookup by view is reusable only when its returned proof is the required witness. Archive gaps are absent storage objects, not protocol emptiness. Ordinary Archive keeps one value per occupied index; MultiArchive supports multiple versions, with index-scoped `has_at` and key ambiguity across indices. A schema and bounded serving policy remain undecided. [Archive contract](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/storage/src/archive/mod.rs#L77), [MultiArchive](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/storage/src/archive/mod.rs#L163).
4. **Keep dense delivery and application recovery separate.** Orderer stops at unresolved slots, emits included slots, skips only authenticated irrevocably-empty slots, preserves terminal identity/protected policy interpretation, and journals exact predecessor/range delivery. Executor's durable receipt, linked to Storage's state/output/cursor/provenance, advances the external applied boundary. Native safety cursor, exported coverage and application applied cursor are different coordinates; no magnitude comparison or automatic GC implication exists. Existing contiguous Journal/Metadata supplies storage primitives, not cross-store atomicity. No new quorum, default schema or actor is selected.

These are minimum responsibility connections, not adopted method signatures or a protocol design. Do not introduce a separate ProofArchive/HistoryResolver application trait or duplicate native crypto/resolver/storage algorithms. The current five public traits remain unchanged.

## What actual chains demonstrate

Alto constructs two existing immutable archives for all finalized certificates and blocks, then passes ownership into Marshal. Its follower selects immutable or prunable implementations behind existing store traits. This supports an owned archive integration, not another general persistence engine. [Alto archives](https://github.com/commonwarexyz/alto/blob/1d87569348b5560699465a72d691d90f18affb9c/chain/src/engine.rs#L192), [handoff into Marshal](https://github.com/commonwarexyz/alto/blob/1d87569348b5560699465a72d691d90f18affb9c/chain/src/engine.rs#L273), [follower store selection](https://github.com/commonwarexyz/alto/blob/1d87569348b5560699465a72d691d90f18affb9c/follower/src/archive.rs#L1).

Tempo's private Marshal alias supplies an immutable certificate archive and a Hybrid block store. Hybrid retains recent blocks in a Commonware prunable archive and serves older material from Reth; eviction uses the execution backend's finalized watermark, and put/sync remains owned/consuming. This is a concrete material-ownership handoff. It does not show a rule for pruning Baton witness/history after an Executor receipt, or implement native Multimmit delivery. [Tempo alias](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/consensus/src/alias.rs#L37), [Hybrid owner](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/consensus/src/storage/hybrid/mod.rs#L289), [handoff/eviction](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/consensus/src/storage/hybrid/mod.rs#L360).

These chain pins use their own Commonware graph. Marshal's Simplex finalization/body interpretation and specialized resolver receiver cannot be copied unchanged for Native Multimmit. Reference their ownership composition only; no chain/backend selection follows.
