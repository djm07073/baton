## Decisive checks and implications

| Potential failure in the proposed recipe | Independent source result |
|---|---|
| Using private engine methods as public integration entrypoints | `sync::sync` is public; Engine/step/apply_operations remain crate-private. `SourceFor` fixes family, operation and digest identity without requiring Clone. Public StateSyncDb also delegates; StateSyncSet is expressly one-time and block-Anchor based. |
| Treating target progress as a usable DB or final result | `is_ready_to_complete` only tests journal size and required pinned nodes. step reports reached before complete. complete syncs the journal, reconstructs DB, compares its **ops** root and invokes persistence. The report correctly forbids stop/ACK on reached_target. |
| Syncing a live DB in place while claiming independent preparation | Config accepts native context/config, not a live DB. fixed Journal::new rewinds/prunes/clears existing partitions; variable Journal::new uses init_sync and resize also mutates. Distinct Rust owners do not justify shared physical partitions. |
| Confusing Current canonical root and sync ops root | The Current Database implementation returns ops_root; its canonical root is distinct. Existing witness checks the connection, caller-owned. sync_boundary is explicitly the latest safe lower bound (or any earlier retained location), not the next execution interval start. |
| Assuming returned DB entails an application-wide atomic import | Current reconstruction persists metadata before return; persist_sync_result is Ok(self), with no output/cursor/certificate transaction. Failed/cancelled preparation can leave persisted native material. Result/outputs and recoverable selected-certificate identity still require the stated handoff. |
| Replacing shared DB without worker fencing | Shared::write removes DB under an exclusive slot; cancellation without put permanently loses the cell. Cloned holders share that cell, and attach_database merely enqueues serving replacement. Neither operation establishes revocation, canonical apply or durable handoff. |
| Treating operation material as a public wire batch constructor | Public apply_batch accepts a locally prepared Arc<MerkleizedBatch>; validate_batch checks local ancestor/bounds applicability. Operation Response/native sync and a prepared local batch remain different paths. |
