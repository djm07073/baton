# Round 8: challenge the full-Baton native gap

Inspected current native source `6233438985d8249d2b2bc1204191d5d405652288` and current reader pages, 2026-10-09. This is a source audit; no protocol implementation, runtime test, new hook or proof is proposed here.

## Finding

The documented gap is real for the stated full-Baton requirement: an authenticated selected cross-lane prefix that every validator preserves in the canonical order after the same immutable frontier. Current callbacks support App-owned payload construction, custody, speculative execution and canonical state application. They do not provide an App policy handoff into native leader construction and voting, or a configurable interpretation of Marshal's output order.

This does **not** mean native leader context is absent or entirely unobservable, that leader proposals lack authentication, or that a body cannot contain App metadata. The native machine already owns exact parent/history/tips, authenticates its canonical proposal, and preserves signing choices through recovery. The missing integration is specifically the selection/adoption/preservation of the additional Baton policy in those mechanisms. A matching speculative order may occur without that extension; it is not the required guarantee.

## Attempted alternatives and concrete limits

- **Set Certified instead of Endorsed.** This can shorten proposed suffixes and change the proposal/extension boundary. It does not encode the identity or order of a chosen report-supported cross-lane prefix; receiving validators accept both existing forms without knowing this local knob.
- **Sort ChainProposal entries.** LeaderBlock validates entry `i` against chain `i`; a cross-chain permutation is malformed. Changing suffix contents changes producer commitments and linked native positions, not the traversal algorithm.
- **Put policy bytes in the transaction body.** App can choose body semantics and commit to those bytes. Native proposal voting and Marshal traversal do not decode them as a leader ordering policy. This supports App metadata, not the documented full-Baton property by itself.
- **Use Inspector or native Reporter to discover a cut.** Existing observations can guide speculative planning. They do not freeze the subsequently selected parent or transfer a prepared policy into the exact signing request. Reporter feedback also does not become an application validity vote.
- **Reorder on Update.** Native output is already canonical. A second App orderer cannot make other validators authenticate the same protected prefix or preserve native replay indices.
- **Use public constructors, verifier methods or mocks signing.** Constructors can describe native objects and verifier methods can check existing signatures. These methods do not change Engine's construction/validation state machine or Marshal's order interpretation. Test-only direct signing is not a production policy extension.

## Reader-document assessment and minimal resolution

The new direction.md paragraph about ProposalPolicy is accurate. For maximal precision, the anchor can be the parent tip when no newer certificate is held; its current reference to a certified anchor follows the source's own enum-level wording and does not create a material incorrect claim. No extra paragraph is needed in consensus/decisions.md: its existing TODO already scopes construction, authentication, pre-vote checking, tip extraction, native Marshal interpretation and recovery correctly.

Keep the gap phrased as missing **policy integration and its proof**, not missing native context/authentication/order machinery. Existing native mechanism reuse remains the simplest design. The audit does not establish that a commitment field or one callback would be sufficient: availability, exact prefix continuation, extension, same-tip evidence changes and view recovery remain open as the current docs state.

Applied the separately requested wording correction in consensus/block-body.md: local verification failure is a fatal Engine error, internally Fatal::Automaton. This avoids implying Running::join publicly returns that typed native fatal value; Round 6 documents the actual lifecycle boundary.
