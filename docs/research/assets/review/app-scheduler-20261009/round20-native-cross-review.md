## Assembly and immediate-ACK copying

The source example starts network channels, builds App handles, starts Marshal and supplies OutputReporter (`examples/log-multimmit/src/node.rs:245–292`). Marshal assembly starts buffer, opens the native service, attaches the supplied resolver bridge and starts its actors (`examples/log-multimmit/src/marshal.rs:123–184`). Native `Engine::open_with` recovers before actor construction (`engine/mod.rs:465–497`), while Marshal open already starts catalog/promoter (`marshal/service/mod.rs:1–11`). The integration page preserves the different startup lifetimes rather than assuming open is uniformly passive.

Example `application/reporter.rs:35–52` notifies its local synthetic App and immediately acknowledges in headless mode, or forwards the complete Update to its sink. It has no transaction-state durable apply contract. `consensus/ordered-input.md:35` explicitly calls this out; the core startup guide and canonical E2E repeat the necessary wiring-versus-consumer distinction. `reference/integration.md` instructs a retained output ingress and exact durable worker instead of copying the immediate ACK. A new App reader therefore has no documented reason to acknowledge merely because the example does so.

The callback shape and native source details are compatible with root's current handling: bounded async propose/verify jobs, honest custody replies, optional metadata admission, synchronous retained Update, canonical work on exact predecessors and ACK only after linked durability. No native vote is delayed for transaction execution, result-signature collection or a Baton approval.
