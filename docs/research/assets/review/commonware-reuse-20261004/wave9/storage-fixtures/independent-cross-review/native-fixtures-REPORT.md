## What the existing Cluster actually tests

Cluster is not parameterized by an application, reporter, body codec, pool or database. Its MockEngineConfig fixes Sha256, Ed25519 transport identity, selected BLS Variant, two MockApplication attachments, NoopReporter, Sequential crypto strategy and simulated Control. `launch_with` exposes four caller-supplied transport pairs and signer/slot identity, but still installs the same fixed attachments. The three data/consensus/certificate receiver parameters share its Rc type; generic Engine's separate impl Receiver inputs are a broader assembly boundary. Thus transport wrapping is possible without editing Cluster; replacing body/execution/reporting semantics is not possible unchanged through this constructor. [Fixed configuration types](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/mocks/cluster.rs#L65), [Launch with transports](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/mocks/cluster.rs#L510), [Fixed attachment construction](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/mocks/cluster.rs#L543).

Public Cluster methods already cover committee/producer-subset construction, start/ready, producer pause/permitted work, link partitions/healing and loss schedules, inspection, served proof lookup and per-engine crash/restart. `tap` registers a raw peer/channel endpoint and `launch_with` accepts such endpoints; re-registering replaces the prior mailbox, so a tap is not an independent passive copy. No additional cluster scheduler or generic traffic dispatcher is warranted. Cluster's delayed sync interval is a public fixture control with its own releaser task; selected fixture intervals/topology/limits do not become Baton defaults. It does not store or disseminate the full body: verify returns its configured boolean/canceled response and Relay simply returns Feedback::Ok. Its first build/verify can be held by a public gate, giving useful callback/pending/cancellation fixture shapes; release of that gate is not durable custody, native adoption, execution certification or state apply. ## Smallest future tx → body → order → execution connection

Reuse the existing deterministic runtime/network and production Engine directly when the test actually needs application behavior. Committee can supply native test epoch/producers/keys/config without importing Cluster's fixed application. Keep these connections under the existing application owners; no new public TestRuntime/Simulator/Harness trait is required:

1. Choose an explicit valid native fixture context/topology and obtain native fixture Scheme/Profile/committee. Seeded deterministic test keys are test material, not production key provisioning, and existing examples with extra nodes do not alter Baton's adopted n=5f+1.
2. Use `Network::new_with_peers` and `Oracle::control(...).register(channel, quota)` for four native planes and the selected application channels. Reuse existing buffer/resolver/archive handles for bodies and TxPool backend attachment. The simulator's configured loss/latency/jitter/bandwidth control already owns link scheduling. It preserves per-link ordering; do not claim link jitter alone produces arbitrary same-link reorder/duplicate schedules. Existing public transport interfaces can host a specifically authorized fault wrapper if a future case needs one; no wrapper is implemented or selected here.
3. Build public EngineConfig with the real application Automaton/Relay/Reporter and start Engine on its native plane pairs. Custody services must be usable before recovery calls Automaton::verify. Engine validates Scheme/Profile epoch/namespace/codec/producers/role agreement; ready means native startup/recovery readiness, not application durable state health.
4. Connect the existing missing authenticated exact-source/policy/dense-order handoff to Orderer and send exact OrderedRange directly to Executor. Native Inspection/finality count/Reporter notices must not substitute for that evidence. Test unresolved-stop, irrevocably-empty skip, included-body wait and immutable segment/prefix interpretation at this seam when its implementation is authorized.
5. Drive actual Executor changes through Storage root/preparation/canonical durability and retained full f+1 result certificate. Compare results only for the same exact order/base/runtime; imported material must preserve ImportedVerified instead of becoming own DirectExecuted work. Optional Baton observations and direction replies remain outside required native/delivery completion. A certificate without applicable material cannot stop unfinished execution.
6. Exercise local node restart and whole-runtime crash separately. Node abort/reopen uses the Engine/Cluster ownership pattern inside a live runtime; `Runner::start_and_recover` → owned Checkpoint → `Runner::from(checkpoint)` reconstructs the deterministic runtime. New runtime loses pending tasks, unsynced storage, network connections and stop signal; rebuild services/registrations, then recover authoritative state/output/cursor/provenance. Neither mechanism constructs multi-store atomicity or confirms a delivery ACK automatically.
