2. **Create existing engines, retain their mailboxes.** `buffered::Engine::new/start` gets the raw body pair and body `Digestible + Codec`/read configuration. These engines supply cache/subscription, network publication, request correlation/peer retry/subscriber lifecycle; typed wrappers are for fitting application messages, not an extra wrapper on those raw engine pairs.
3. **Keep one existing archive owner behind request handles.** Existing Identifier Key/Index lookup or a suitable MultiArchive schema binds authenticated header→exact producer context/commitment→bytes/required-parent header references. Producer clones the owner's request handle; owner lookup/encoding responds through existing oneshot/Bytes. Consumer validates the expected key/content and hands valid material to the same custody processing. Occupied/below-floor puts, digest/context aliasing and pruning make exact retained presence plus covering sync essential. Schema/backend/limits remain unchosen.
4. **Implement native Automaton and Relay directly.** `propose(Context)` selects stable bytes from the chosen TxPool, builds bounded encoded body, establishes exact body/parent custody and resolves its digest receiver. Native Core signs the header. `verify(Context,digest)` looks up/subscribes/fetches and resolves true only after correct expected content/parent/context/custody; missing/bad response/local failure is distinct from permanent expected-payload invalidity. `Relay::broadcast(digest, ())` schedules retained-body lookup then `buffered::Mailbox::broadcast_shared`; local Feedback is not peer custody ACK. Full fetch envelope size, not just tx bytes, must fit transport.
5. **Join opportunistic exact header/body observation independently.** Reporter passes accepted TransactionBlock artifact/context to the shared attachment/Baton intake; StoredBody can arrive first or later. Compare body commitment, exact header identity/context and accepted provenance before CandidateBlock. Producer header parent is not the execution parent. Baton constructs parent-linked Executor input on its selected exact path; candidate loss only loses speculative opportunity, not canonical truth.
6. **Preserve canonical delivery separately.** Narrow recoverable native selected-source/private-extraction and policy/history bridges feed Orderer using existing verification/archive/resolver/journal/metadata. It stops at unresolved slots, fetches missing included content, and delivers exact irrevocable input directly to Executor. Executor controls effects/certification/sync; Storage selected roots/apply/durability; durable receipt returns to Orderer/TxPool without Baton approval. Native replay/inspect/serve/Reporter are not a complete external dense history stream.
7. **Start and release under the correct lifetimes.** Prepare/open custody first; make separate body fetch usable while `Engine::start` verifies recovered payloads, before Native Running returns. Idle preparation can precede network binding; active sends cannot. Covering archive sync, native ready milestone and runtime task termination are separate. Cancellation/native Retire/cache eviction does not release custody/query/worker/sync/serving obligations; no new recovery/supervisor/body engine or peer Ready gate follows.
