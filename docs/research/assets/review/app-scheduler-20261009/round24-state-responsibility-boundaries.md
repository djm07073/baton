## Counterexamples that preserve the separation

- A producer authenticates two contexts containing the same transaction body. Native references are different headers; App pool deduplication is transaction-specific, while execution reuse additionally needs exact ordered input and execution predecessor. Neither deduplication relation substitutes for the other.
- A native payload becomes Valid for DA, but App never speculates it because its optional work budget is full. Marshal can still deliver the canonical block; native `ValidationState::Valid` carries no effects/checkpoint to apply. The existing canonical-first handler therefore remains necessary.
- App finishes two attempts for the same block against different cross-lane parents, or receives a late completion from an abandoned attempt. Native BuildId/ValidationId and custody retention do not identify those application attempts. App's exact-parent/attempt fences remain required without duplicating native validation.
- App state becomes durable and crashes before Marshal's ACK cursor sync. Delivery's Exact window and separate cursor persist only delivery progress (`actors/delivery/actor.rs:303–327`; `acks.rs:1–5,105–121`). Marshal can redeliver; its progress alone cannot establish whether this App already applied the effects. The App applied record is the recovery evidence.
- Native CertificateRecorded release or a coordinated floor permits body pruning. Those are native custody/order boundaries, not permission to delete a still-used execution checkpoint or query/result material. Conversely, App dropping optional candidate metadata does not make a payload invalid. Current block-body/ordered-input text already distinguishes these lifetimes.

## Disposition

The design reuses Marshal's full-block custody, native proof/history reconstruction, dense order and ACK machinery directly. It retains one App transaction pool plus shared candidate/execution/applied metadata because those facts are absent from the native public API. No current responsibility could be removed by simply substituting an existing native pool, catalog or progress method. No additional reader prose, trait, wrapper, body resolver or persistence framework was added. The concrete App representation and resource policies remain implementation work.
