Current adopted requirements:

- Latest reuse decision (2026-10-04, six-hour research goal): separate execution from storage. Executor emits completed transaction changes/batches and retains execution-path selection, worker/tree control, result certification and normal-path peer state-sync orchestration. Storage owns root calculation, state material, canonical database application, durability and physical retention/recovery beneath that control. Do not require commonware_glue::stateful::Application or the full Stateful actor: returning Merkleized from every execution attempt can force hashing before it is useful. Reuse QMDB batch/database primitives directly; existing sealed-parent fork APIs do not by themselves implement root-deferred branching. Body dissemination should reuse Commonware broadcast/resolver/archive/network components, with only the native/body/custody adapter added. Investigate actual Commonware-based chains and ecosystem mempools rather than assuming a queue/provider is a complete pool or prescribing new generic infrastructure. Keep existing reader-facing pages; source-pinned investigation and independent review belong in assets/review/commonware-reuse-20261004. The six-hour goal remains active until its entire requested research/review/publication scope is verified.

- Earlier comment/correction decision (2026-10-04, superseded only in body/storage boundaries by the latest reuse decision): five public application traits were TxPool, BlockService, Orderer, Baton, Executor. TxPool absorbs analyze/classify; Executor absorbs transaction execution and sign_result/collect_result/verify_result/result_certificate. No separate TxPolicy, Runtime, ResultService, or Planning-inside-Executor section. Direction candidate selection is Baton::plan, not Executor::plan. Executor exclusively owns parent-linked execution, canonical promotion/pruning, certification and state sync. Reuse Commonware callbacks, crypto, QMDB and P2P beneath these application contracts; do not call a custom wrapper a ready-made upstream primitive. This corrects the earlier eight-trait/Executor-planning design.
