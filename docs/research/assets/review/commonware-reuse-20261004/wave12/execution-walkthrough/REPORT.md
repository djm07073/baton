## Decisive actual source boundaries

The inspected native `DatabaseSet` declaration has `Unmerkleized: Send`, `Merkleized: Clone + Send + Sync`, applied-base `new_batches`, `fork_batches(&Self::Merkleized)` and `finalize(...)->Barrier` (`glue/src/stateful/db/mod.rs:508–567`). Cancelling by-value canonical mutation is documented to lose the affected databases; a trait's `&mut self` or worker generation cannot provide the shared fence automatically.

Concrete Any wrapper `get` acquires applied DB read authority before batch lookup, `stage(self,...)` consumes its wrapper and `write(self,...)` records mutations (`glue/src/stateful/db/any.rs:110–152`). Reads are not independent immutable snapshots. Existing concrete `validate_batch`/`apply_batch` (`storage/src/qmdb/any/batch.rs:2733–2763`) supply storage applicability/application, not full execution subject, durable outputs/cursor or provenance. These facts explain the existing access/retention and selected-root integration text; no guessed generic reader/fork interface is needed.

Public `qmdb::sync::sync(Config<DB,S>)->Result<DB,...>` (`storage/src/qmdb/sync/mod.rs:55`) returns a reconstructed DB. The engine reports reached-target before journal sync, DB reconstruction, root check and persistence (`sync/engine.rs:724–803`). This confirms why progress, completed storage candidate and application-authorized canonical import must remain separate. The existing reader prose does not promise that this raw DB can be mechanically passed as DatabaseSet's sealed batches or directly installed into a live writer.
