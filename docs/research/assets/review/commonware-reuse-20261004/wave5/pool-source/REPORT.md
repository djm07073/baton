# Smallest conditional Nunchi actor source adaptation

**The whole pool actor is separable from the SDK chain builder. Keep its one actor, cloneable handle and private nonce/digest kernel; adapt the small SDK payload boundary, package graph and missing lifecycle hooks.** Source inspection supports this as a realistic conditional reuse route. It is not a compiled port, selected backend or unchanged crate import.

Wave4 already documented the public handle/completion and dependency-identity gaps. This wave identifies the actual files that need attention. It found **no additional existing primitive** that supplies source-aware feature admission, acknowledged canonical pool processing, restart readiness or byte/dependency selection unchanged. Those gaps can be addressed inside the existing selected actor/attachment instead of another pool, dispatcher or account-reconciliation engine.

Read latest AGENTS/README/BATON_HANDOFF and current canonical Tx/body/interface/integration context. Reviewed source pins are SDK `eea35ced709f68c15d6fbc8bcc754696a7e44374` and native Commonware `534af0ede48affd35b2111522527547b4cc9bf72`. [Fresh manifest](source-manifest.json) retains **32 successful fresh source downloads**, all matching their paths in fresh complete recursive Git trees; one exploratory nonexistent common/src/module.rs 404 is recorded and excluded. Sources are [retained locally](sources/). Official Cargo workspace feature-inheritance documentation was also checked. No runtime code, dependencies, native build/tests or canonical docs were changed.

## 1. Exact source boundary: the actor does not depend on the chain

| Source unit | Already reusable responsibility | Narrow adaptation boundary |
|---|---|---|
| mempool/src/pool.rs | Private Pool, per-lane BTreeMap, digest index, ready-lane bookkeeping, cloned selection, refresh/remove/TTL/status updates | Preserve one owner. Add selected canonical readiness/replay fencing only where needed; count selection and concrete replacement/eviction/TTL policies are not Baton defaults. |
| mempool/src/actor.rs | Public Mempool/MempoolHandle; one Message enum, mpsc owner loop, oneshot submit/pending/status completion, optional raw P2P ingress/gossip | Source-aware common admission hooks, bounded configurable decoder if chosen, reliable canonical responder/readiness and typed selection error are missing public surfaces. Extend this owner, not an external duplicate queue. |
| mempool/src/tx.rs | Generic PoolTransaction contract for a custom tx | SDK imports and adapter are localized here: Address/Operation/Transaction, SignatureError, SDK NonceKey and blanket impl. Retain if SDK payload is chosen, or isolate them as an optional compatibility adapter in a maintained source extraction. |
| mempool/src/lib.rs | Module ownership, stability annotation, public exports | Gate/adjust SDK NonceKey export when its tx adapter is isolated. Keep private Pool private; callers need handles/completion, not unfenced state access. |
| mempool/src/config.rs | Existing count/single-tx/mailbox/status/TTL knobs | Supply chosen config explicitly; copied numeric Default and fixed policy behaviors do not become adopted policy. |
| mempool/src/status.rs, error.rs, metrics.rs | Status cache/error enumeration/Commonware metrics | Reuse. Status history is in memory; adding source metrics or a selected policy refusal may need a narrow enum/error change. Do not call policy rejection invalid signature by accident. |
| mempool/Cargo.toml and host workspace declarations | Existing dependency/package structure | Reconcile every used native Commonware identity, inherited metadata/lints and optional SDK dependencies. Changing one runtime import does not port the actor graph. |

The private kernel is `pub(crate) struct Pool`, and lib.rs does not export it. actor/pool/config/status/error/metrics have no Nunchi chain or Stateful Application import. Only tx.rs imports nunchi-common/nunchi-crypto. This is why whole **actor/kernel source** reuse can avoid the SDK chain lifecycle. The actor's private Message and handler are available to a maintained source adaptation, but are not externally callable public hooks. [Private Pool](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/pool.rs#L22), [Exports](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/lib.rs#L10), [Localized tx imports](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/tx.rs#L1), [Actor imports/message](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/actor.rs#L1).

### Retain the existing task and handle surfaces

Keep `Mempool::new`, cloneable MempoolHandle, `start`/`start_p2p`, `submit`, `pending` and `status` concepts wherever compatible. Native Commonware already publicly reexports **ContextCell** from utils::Cell, supplies `spawn_cell!`, Spawner/Handle/Metrics and metrics constructors/labels. Native macros exports select_loop and stability_scope. Native P2P supplies raw Sender/Receiver/Recipients, IoBuf input and synchronous send feedback. The source port therefore needs no replacement task framework, typed dispatcher or connection engine. This is a source/API correspondence, not proof that all SDK uses compile after retargeting. [ContextCell reexport](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/runtime/src/utils/mod.rs#L24), [spawn_cell](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/runtime/src/utils/cell.rs#L6), [Native metrics](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/runtime/src/telemetry/metrics/mod.rs#L60), [Native Sender](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/p2p/src/lib.rs#L139).

## 2. Retained dependencies: two conditional routes

**Keep SDK payload types if they fit the chosen workload.** Then source-adapt mempool plus relevant common/crypto imports onto the native graph. The default SDK NonceKey is namespace + Address; its Transaction signs an account/authorization/payload subject and supports SDK single/multisig policy. nunchi-crypto fixes tagged Ed25519/Secp256r1 account keys/signatures. Those are workload semantics, not transport keys or an adopted Baton scheme. A custom PoolTransaction can provide another NonceKey and VerifyError but unchanged tx.rs still imports/compiles the SDK blanket adapter. [Default nonce adapter](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/tx.rs#L7), [SDK signing subject](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/common/src/transaction.rs#L61), [SDK crypto curves](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/crypto/src/lib.rs#L17).

nunchi-common's default **state** feature includes optional glue/runtime/storage/parallel/utils. Its lib.rs gates state_db/runtime modules and exports behind that feature, while account/transaction/events remain unconditional. No inspected mempool source uses the state-gated exports, so disabling state is a source-supported candidate for this pool-only dependency graph; it is not a compiled feature configuration. Defaults are additive across the resolved graph. Because the SDK uses edition 2021 and workspace-inherited nunchi-common without disabling defaults, a one-line member-level default-features=false may be ignored/rejected under applicable Cargo rules; reconcile the inherited declaration and actual feature graph. Another selected dependency can re-enable state. Do not claim pool-only means state-free until the chosen graph is checked. [Common feature table](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/common/Cargo.toml#L10), [Gated modules/exports](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/common/src/lib.rs#L4), [Workspace dependency](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/Cargo.toml#L52), [Cargo workspace dependency inheritance](https://doc.rust-lang.org/cargo/reference/workspaces.html#the-dependencies-table).

**For a custom payload, isolate the SDK adapter instead.** tx.rs's generic trait itself needs std and native SHA-256 Digest; the SDK NonceKey struct and blanket Transaction impl are separate units. Gating/extracting that adapter and its lib.rs export permits retaining the entire actor/kernel implementation while removing unused common/crypto dependencies from the maintained pool manifest. This is source maintenance with provenance, not an upstream generic pool artifact already offering that feature. The unchanged manifest does not offer this separation. Neither route requires nunchi-chain, its builder or Stateful::Application. [Trait versus blanket impl](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/tx.rs#L32), [Current manifest](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/Cargo.toml#L10).

The actor still assumes concrete SHA-256 Digest and monotonic u64 nonce lanes. Replacing either assumption would affect actor/pool/tx/status-facing types and algorithms, so it is not the small payload-adapter extraction above. Assess fit before selecting it; do not quietly generalize the whole pool to justify a predetermined backend. Native/release package reconciliation remains mandatory even if both digests are 32 bytes.

## 3. Minimal missing hooks belong in the selected existing owner

### Source-aware payload admission

`submit`/`submit_many` perform check_stateless before mailbox admission. Built-in peer handler boundedness is left to T::read_cfg(unit), then check_stateless and admit_verified run directly. P2P-mode local messages gossip, peer messages do not. Source metrics already distinguish Rpc/RpcBatch/P2p internally, but this enum is private and no source-aware public submit exists. [Local admission](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/actor.rs#L61), [Peer path](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/actor.rs#L473), [Source metrics](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/metrics.rs#L33).

If filtering occurs only during packing, the whole actor can keep its ingress behavior and TxPool::analyze/classify sees selected payloads there. If admission routing/filtering is chosen, connect the same pure hook at both local and peer admission sites, with explicit source disposition/gossip behavior in existing actor.rs. Reuse submit's oneshot admission result; no second queue is needed. Check stateless validation remains distinct from Features/Decision: current check_stateless translates every VerifyError to InvalidSignature, so policy exclusion cannot simply be smuggled into that error without altering its meaning. Live nonce/state lookup stays in pool/Executor maintenance, not analysis. The exact hook/decision schema and worker placement remain open. [Error translation](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/pool.rs#L81).

If chosen payload decoding needs a non-unit config, adapt existing actor.rs startup/receiver to carry selected decode bounds, or use a selected bounded ingress with local-only actor start. Whole-frame exhaustion, transport max, nested allocation/work and aggregate submit_many limits require explicit boundary checks. Reusing its one-shot gossip does not supply inventory/fetch/retry; don't add those engines unless the selected delivery policy requires them.

### Reliable canonical processing and restart readiness

The existing Finalized message carries digests, lane_nonces, height with **no responder**; the public method uses try_send and returns (). It cannot prove processing or seed completion, and status/pending cannot query processed nonce context. The narrow source adaptation is to add reliable submission and an existing oneshot-style response/watermark through **the same Message/handle/handler**, not a parallel commit actor. Return processed completion only after the owner has applied the selected linked canonical outcome. If on_commit instead acknowledges retained recoverable work, name that meaning and keep selection reconciliation explicit. Awaiting mailbox/responder does not make caller cancellation undo an already processed mutation. [Message fields](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/actor.rs#L20), [Lossy finalized](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/actor.rs#L195), [Existing processing site](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/actor.rs#L414).

Keep the watermark bound to actual durable Executor/Storage context/range, not just a native lane height. Exact representation remains open. Replayed older finalize can overwrite status height despite monotone nonce checks; reject/recognize duplicates and incompatible outcome contexts before mutating. A newer update concerning only lane B does not repair a lost A update. Reuse existing Pool::finalize for nonce/digest/ready-index changes after that contextual check; reconstruct/replay from already retained durable canonical state/results rather than propose another pool reconciler. [Current finalize](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/pool.rs#L211), [Status overwrite behavior](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/status.rs#L35).

New Pool starts with empty committed_nonces, defaulting unknown lanes to zero. Its existing finalize(empty digests, authoritative nonce snapshot, canonical progress) can perform initialization if processed under the chosen actor readiness contract. This avoids inventing a second nonce engine. Snapshot hydration must cover relevant lanes, or a newly encountered lane needs authoritative initialization before eligible selection; unknown does not prove its canonical nonce is zero. Bound snapshot/replay work, and do not expose ready selection before required hydration. Initialization through `finalize` is not side-effect-free: it also sets `last_height` and runs TTL eviction. Transactions admitted before hydration carry the earlier `last_height` (zero in a fresh pool), so a high hydration height can immediately expire those entries. Hydration/admission ordering and the chosen lifetime semantics must therefore be explicit before using this path; no ordering or TTL policy is adopted here. [Admission height](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/pool.rs#L128), [Finalize height and expiry](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/pool.rs#L211). No schema/seed method is adopted here. Candidate retention/admission durability/status persistence remain separate. No pool processing/watermark becomes a native cut/direction gate or substitutes for Orderer durable ACK.

### Count/byte/dependency selection

Keep existing pending(count) clones and ready-index kernel. The selected native body attachment can enforce bounded work, full-body/fetch-response byte limits, per-build dedup, selected payload policy and dependency-preserving packing. Omission of nonce k requires exclusion/re-evaluation of its dependent successors; later same-nonce replacement cannot mutate already selected bytes. Refills can return the same txs. No reservation/unselect engine is needed solely to cancel a clone-based build. If actor-side byte/dependency selection is later chosen, extend Pending/Pool::pending in those two files rather than another pool, but that algorithm and policy are unselected. [Selection](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/pool.rs#L160), [Readiness bookkeeping](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/pool.rs#L307).

Current handle pending returns empty on shutdown, so a selected processed/readiness contract must distinguish shutdown from healthy-empty rather than claim Vec alone proves readiness. PoolTransaction's Clone+Send+Sync bounds also do not enforce immutable custom payload content. Entry caches digest once, while pending/gossip clone T. A chosen custom tx must maintain stable verified identity/encoding/features throughout admission/selection or freeze that material; otherwise changing interior shared data can desynchronize cached digest and returned bytes. This is a payload-type contract, not a new queue. [Public pending completion](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/actor.rs#L175), [Cached digest](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/pool.rs#L13).

## 4. Proposed implementation connection checklist for reader docs

For tx/interfaces.md and integration.md, a short conditional checklist is more useful than another interface or crate catalog:

1. **Fit and retain one owner:** selected SHA-256/nonce-lane payload; reuse Mempool/MempoolHandle and private Pool modules. No backend choice is made by this checklist.
2. **Resolve the native graph:** maintained pool manifest plus retained common/crypto adapter, or isolate that optional adapter. Check inherited feature graph and all cross-boundary Commonware types. No chain builder/Application is required.
3. **Connect payload hooks once:** packing-only analysis may wrap existing pending; admission policy must reach both existing local and peer sites with explicit source behavior. Preserve stateless validation versus classification and stable tx material.
4. **Complete canonical maintenance in the existing mailbox:** actual durable outcomes → context-bound processing/replay/readiness → existing finalize kernel. Use the same handle/oneshot owner; startup hydration and lost updates are not supplied unchanged.
5. **Select and retain exact producer body:** clone-based candidates → dependency-aware bounded packing under native producer Context → archive custody → existing Automaton digest. Local cancellation does not retire txs or release native custody.
6. **Keep unresolved choices explicit:** policy values, source/decision/watermark encodings, snapshot scope, filtering placement, retransmission, duplicate execution, admission durability and package port validation remain open.

This is a proposed file/connection recipe, not an adopted schema or changed Rust trait. The current five public declarations need no additional generic dispatcher/reconciler trait to express it.

Whole Reth remains a separate conditional route when actual Ethereum provider/transaction/network/maintenance types fit; its public origin/canonical-update/maintenance surfaces already cover more of these lifecycle operations, but cannot be imported as an opaque-payload Commonware pool. Constantinople source remains a fixed-transaction/private-admission/destructive-selection alternative; extracting only its queue is not unchanged generic reuse. The prior source receipts and exact comparison are [wave4 pool-builder](../../wave4/pool-builder/REPORT.md). This wave adds no new evidence that either alternative fits an undecided workload.

## Limits

Source-local separation demonstrates a plausible minimal maintained port; it does not prove build compatibility, bounded end-to-end processing, production maturity, result safety or Multimmit integration. The SDK actor's hardcoded replacement/round-robin/TTL/eviction/status policies and default numeric config require explicit selection if adopted. Existing primitive reuse cannot settle these policy or protocol questions. No runtime implementation or external checkout was modified.
