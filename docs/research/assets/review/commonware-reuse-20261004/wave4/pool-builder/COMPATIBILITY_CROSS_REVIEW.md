Public actor startup with P2P additionally requires that graph's Sender/Receiver agreeing on PublicKey and `T: Encode + Read<Cfg=()>`; local-only start does not require that codec bound. This public generic actor is a strong conditional **source** reuse candidate, not an unchanged native handle consumer. [Transaction trait](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/tx.rs#L32), [Startup bounds](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/actor.rs#L278).

A custom PoolTransaction does not eliminate those Cargo dependencies. The report correctly recommends reviewing feature/dependency adaptation without pretending it has been performed. ## Cargo semantics checked against official documentation

Read the official Cargo Book dependency, patch and resolver pages independently through browsing. The report's practical conclusion is correct: same public import/type spelling is not equality across distinct resolved package identities, and patch selection remains constrained by the requested version. The native package's 2026.7.0 version is below the ordinary `2026.9.0` caret requirement, so a source patch alone cannot satisfy that requirement unchanged. A dependency's own patch/lock declarations do not automatically make a consumer adopt the intended graph. Reconcile all crossing direct/transitive Commonware identities rather than changing one visible runtime import. [Cargo patch selection](https://doc.rust-lang.org/cargo/reference/overriding-dependencies.html#the-patch-section), [Dependency locations/version role](https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html#the-role-of-the-version-key), [Distinct-version type hazards](https://doc.rust-lang.org/cargo/reference/resolver.html#version-incompatibility-hazards).

No need to change the report's stated alternative of a release-isolated component with explicit byte/application bridging: it is qualified as an alternative, not native handle reuse. The primary recommendation to adapt the existing actor into a coherent native graph fits the user's reuse intent and avoids a parallel pool.
