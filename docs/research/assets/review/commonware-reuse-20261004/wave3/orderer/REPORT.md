# Orderer: reuse verification, records and storage; add only the native-to-order bridge

Investigation date: 2026-10-04. Baseline reader docs: GitBook revision `NY491pkJQdX6ny2Lyndj`, GitHub `3c5ec96c91883dae892ee99832dee315c789eaee`. This is source research and a documentation recommendation. No canonical pages, protocol, dependency or external checkout were changed.

## Concrete result

**Orderer should interpret and deliver exact input, not implement another proof system, archive, backfill transport or cursor database.** Several parts that the present page describes generally can be named as direct Commonware calls. Reuse the native cryptographic Scheme, reversible certificate tally, public history record codecs, generic archive gap index, generic resolver, journal and metadata store. Keep the proposed Orderer trait as the application boundary; none of these primitives already derives Multimmit's dense application order.

The remaining native modification can be described more narrowly: an owner-selected witness handoff plus access to the existing private tip/history extraction, and the Baton policy/adoption integration already acknowledged as unresolved. Public compact-tally reconstruction and certificate verification do not require that facade.

## Where public reuse stops

### Existing handles are useful reads, not a reliable stream

- [`Activity`](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/types/activity.rs#L12) currently has only `ProtocolAccepted { artifact_id, artifact }`. It supplies an exact admitted artifact as `Arc<Artifact>`, but no selected finality pool/revision or durable delivery handoff. Voter ignores the returned reporter Feedback at [actor.rs L1659](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/actors/voter/actor.rs#L1659) and [L1861](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/actors/voter/actor.rs#L1861). Recording notices opportunistically is useful; it cannot be the only authoritative recovery source.
- [`Inspector::inspect`](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/engine.rs#L536) is a bounded best-effort query; enqueue rejection or a stopped owner returns None. [`Inspection::finality`](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/machine/state.rs#L450) reports latest normalized facts only. `ready_artifacts` gives IDs, not a public get-artifact/export API. Polling can miss intervening same-tip source revisions.
- [`Running::serve(view)`](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/engine.rs#L572) reads a proof the existing native resolver retains. Its [selection](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/actors/resolver/actor.rs#L289) returns a covering L-QC whose view can be greater than requested. Retaining a newer L-QC discards covered exact exits; native pruning discards old exact view evidence. None does not authenticate absence or nullification. A covering proof can advance native recovery while failing an application query for the exact original witness.

### Public spelling does not imply application-callable machinery

`multimmit::machine` and `multimmit::storage` are implementation-private modules. Selected types are re-exported at [multimmit/mod.rs L242](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/mod.rs#L242); production drives Engine. The native SafetyJournal and CheckpointStore are not application storage APIs. Copying their partition bytes would couple Orderer to the native safety state, pruning and replay format.

The native resolver Actor/Config/Mailbox are visible, but its reliable commands carry machine-issued `ResolutionJob` and apply machine-owned Retain/Prune controls. `ResolutionJob` is not publicly re-exported for applications; manufacture/test facades are not production integration. This actor is documented as fixed-epoch **view proof** recovery, excluding application-chain history ([resolver/mod.rs L1](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/actors/resolver/mod.rs#L1)). Continue using it inside Engine; use the generic resolver for exact external history material.

Public `Artifact::id<H>` and `Artifact::unverified` are reusable, but `Artifact` itself does **not** implement Read/Write/Codec at this pin. Archive requires `Value: Codec`. Therefore do not promise `Archive<..., Artifact>` unchanged. Retain a bounded application envelope using existing variant codecs, or archive `ViewProof`/typed records directly. An envelope must preserve the upstream artifact domain/tag and verify exact object identity; no native wire format is invented here. [`Artifact` APIs](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/machine/admission.rs#L85).

### Native extraction remains private

`FinalTips::from_pool` is [`pub(crate)`](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/machine/algebra/tips.rs#L336), and the algebra module is private to the crate. Public tally expansion does not expose final-tip/settledness extraction or validate a history link's native safe-tip derivation. A narrow facade over these existing functions is less work and less duplication than a second extraction algorithm; it is proposed integration, not a currently callable API.

The owner's DirectPool preserves selected identity/body/source provenance, while an aggregate row may have no standalone raw signature. The native evidence digest ([finality.rs L2082](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/machine/finality.rs#L2082)) hashes selected per-identity bodies, not every original cryptographic witness. Do not replace the source by an arbitrary `n−f` subset or infer it from the normalized tip alone. Waiting only for a later L-QC is an optional local evidence strategy with different latency/source selection, not equivalent to exporting the sticky pool at native finality.

## Smallest proposed native hooks

No hook API or protocol code is implemented by this review. The design should specify these obligations, then choose exact shape in the already-open integration decision:

1. **Export the owner's selected revision:** exact leader/parent/history, original selected raw vote or authenticating source-certificate rows, projection, source transition identity, and durability/replay linkage. Replay/resumption must not depend solely on notices or latest inspection. Same tips with changed settledness/source remain distinct transitions.
2. **Expose existing extraction through a narrow read/verify facade:** safe-tip/final-tip/settledness computation and history advancement for the supplied exact owner-selected source. Reuse public Scheme and tally operations around it. Keep authority over proposal choice, observation order and accepted sources inside the existing owner.
3. **Preserve material until the external handoff is recoverable:** specify retained exact policy/history/header/witness references and serving requirements. This is not blanket permission to have Executor delivery ACK block native votes/cut or to repurpose consensus Retire. The capacity/retention bridge still needs a proof compatible with native resource bounds and independent consensus progress.

Baton's selected-prefix policy adoption/availability/continuation work is separate from this read/export facade. A facade cannot authenticate a new policy, guarantee inclusion or solve exact leading order by itself.

## Local storage and backfill wiring

The current Orderer interface can be implemented by one application attachment holding upstream handles. No additional Orderer server or actor is required by this reuse recipe.

- `record(evidence)`: existing Scheme verification → exact-context/source checks → upstream archive/write barrier for original witnesses and public history records. Preserve immutable identity and all required source revisions. A plain view-indexed Archive put would silently keep only the first evidence at that view; choose MultiArchive or a unique ordinal schema deliberately.
- `next_range()`: interpret verified terminal slots/history/policy using the narrow native bridge; use archive gap APIs to find *stored-object* holes and generic resolver for known missing keys. A disk hole and a protocol unresolved slot are different. Emit only a continuous irrevocable sequence and retain its stable application range identity for redelivery.
- `acknowledge(CommitResult)`: validate the exact predecessor/range and linked durable application result, then commit a small metadata record or append an acknowledgement record to the existing journal. Distinguish native journal `Cursor` from the application's emitted/delivered cursor. QMDB, journal, archive and Metadata do not form an automatic shared atomic transaction; crash ordering/linkage remains the application contract.
- `recover(...)`: upstream bounded replay and read operations recover local records; verify source references and durable state linkage before restoring emission/ack cursors. Redeliver unacknowledged retained ranges idempotently. Never rewind authenticated emitted choices or reinterpret missing bodies as empty.

This is an available primitive recipe, not an adopted concrete schema. `start_sync` completion covers captured writes; later writes need their own barrier. Do not treat local append success, Archive admission, Reporter acceptance or readable QMDB as a durable Executor delivery ACK.

## Reader-page changes recommended

1. **docs/consensus/ordered-input.md:** add a short public-call table for Scheme, Tally, TipRecord, ViewProof, archive gaps, Journal and Metadata. Clarify that only selected-source export and private extraction require native hooks; compact transcript opening is already public.
2. **docs/reference/integration.md:** add “Orderer assembly” beside body and storage assembly: native verification/typed records → generic archive/resolver → native extraction facade → continuous range → existing journal/metadata cursor. Mark concrete schema/retention/facade as open.
3. **docs/e2e/recovery.md and verification.md:** distinguish exact-history archive backfill from native covering-view recovery; add cases for same-view evidence revisions, lost activity notice, missed inspection revision, None under query backpressure, wrong old cursor/state linkage, and source-certificate row reconstruction without standalone votes. These are future verification obligations, not executed tests.

No public trait deletion is justified: Orderer still owns semantic exact-order interpretation and delivery. No new policy default is selected.
