# Executor result transport: native reuse audit

Reviewer: `/root/reuse_network_v3`. Baseline: `8b61492bbebdbf34dbc10e5d43c3117e19618377`. Source/API audit only; no implementation, build, protocol execution, codec/scheme/quorum/backend or budget selection. Application f+1 semantics and the five public traits remain unchanged.

## Main result

Use existing authenticated channel pairs and typed P2P for incoming signatures/certificates. Buffered broadcast can share/cache an identified artifact; generic resolver already fetches retained artifacts with retries. For QMDB operation material, use the existing DB P2P Actor and its Source mailbox directly. Collector is only a conditional pull-style signature solicitation adapter, not a required result module or a certificate verifier. None of these provides certified-result switching, provenance or canonical writer authority.

The concrete missing connections are small application adapters: typed message/subject identity, verification and validated signer collection inside Executor, retained artifact lookup/serve under its existing owner, and Storage authorization of an exact certified sync target. Do not add another generic ResultService, transport, fetch or retry actor.

### Buffered broadcast is a digest cache, not a signature accumulator

The cache globally stores **one `Arc<M>` per `M::Digest`**, with peer deques/refcounts controlling residency. If different validators' response objects all use only the common execution-statement digest as `M::Digest`, they collapse into one resident cache object. Distinguish an identified response/certificate/material artifact from the full execution subject used to group validated signatures. The chosen artifact key must identify the object being cached; no hash algorithm or envelope is selected here. [Cache insertion](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/broadcast/src/buffered/engine.rs#L327).

`subscribe`/`get` needs a known digest. It does not expose an arbitrary incoming-signature stream or initiate a peer fetch. Unknown artifact discovery therefore needs a typed message/known identity connection in the existing Executor receiver, not an assumed broadcast callback. Subscribe waiters can receive an object even when its sender is outside `latest.primary`; primary eligibility affects cache residency, not result-signing authority or validation. Peer-provider membership, transport sender, artifact identity and eligible original signer are four distinct things. No broadcast receipt counts toward f+1. [Cache/get/receive](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/broadcast/src/buffered/engine.rs#L253), [waiters](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/broadcast/src/buffered/engine.rs#L299).

### Resolver subscribers are local context, not peer identity

`Fetch { key, subscriber }` sends the key; subscribers remain local and accompany delivery. Consumer validates the response against the peer-visible key separately from whether it satisfies the retained execution generation/base/target subscribers. Complete retires delivered subscribers; Ambiguous retries a valid alternative without blame; Invalid means invalid for the peer-visible key; Ignored retires the key without retry. A stale local generation or unavailable local Storage is not automatically peer-invalid. Do not use Ignored as a retry instruction. Targeted retries stay within targets and current primary eligibility; they do not establish signer/custody availability. [Delivery contract](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/resolver/src/lib.rs#L114), [targeting/subscribers](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/resolver/src/p2p/mod.rs#L25).

Generic resolver's serving pool is unbounded; Producer owns admission and must be able to drop a request. Existing mailbox/channel quotas do not alone bound all application decoding, material verification, pending subscribers or retained artifacts. This is a placement obligation, not new numeric budgets. [Pool contract](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/resolver/src/p2p/engine.rs#L77).

### QMDB material has an existing actor, but a narrower protocol

`Source::serve(&self, Request<F>)` returns operation proof material and optional local verification feedback. Request is Operations(size,start,max_ops) or Boundary(size,start): it carries no execution subject, epoch, trusted root, outputs or provenance. Storage/Executor must bind the authorized sync root/range to the verified certificate and compatible authenticated history. Reusing this Source does not turn arbitrary application deltas/outputs into QMDB operations. For separately encoded retained certificate/output/material bundles, generic resolver Producer/Consumer can still be attached to the existing owner. [Request](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/storage/src/qmdb/sync/source.rs#L21), [Source/feedback](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/storage/src/qmdb/sync/source.rs#L385).

Two integration caveats are concrete:

- `Mailbox::attach_database` enqueues replacement, and AttachableResolver returns an immediately ready Future. This proves neither processing, selected DB serving readiness, retention nor canonical writer handoff. Actor processing replaces its serving DB. Storage must keep certified material retained and connect the correct serving handle; do not add a consensus ACK barrier or treat that Future as a durable fence. [Enqueue/ready](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/glue/src/stateful/db/p2p/mailbox.rs#L124), [replace](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/glue/src/stateful/db/p2p/actor.rs#L231).
- The actor coalesces equal numeric Requests, decodes one response, fans it to local Source callers, then awaits their proof feedback inside its actor loop. This is local verification feedback, not another network ACK or execution vote. Complete/drop this feedback after its defined proof check; delaying it through certificate collection or canonical apply would unnecessarily stall that service's mailbox/serving loop. Because numeric request identity omits trusted history root, incompatible concurrent target histories cannot be assumed safely interchangeable. Bind chosen Source sessions to compatible authenticated history. This is a source contract limitation, not an observed Baton bug. [Fan-out/approval](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/glue/src/stateful/db/p2p/actor.rs#L275), [proof feedback before storing](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/storage/src/qmdb/sync/engine.rs#L558).

## Collector: conditional reuse, with transport-count caveats

`collector::p2p::Engine::new(context, Config<B,Monitor,Handler,RqCfg,RsCfg>) -> (Self, Mailbox<P,Rq>)`; `start(request_raw_pair, response_raw_pair) -> Handle<()>` uses **two** typed channels. Rq must implement Committable+Digestible+Codec; Rs commitment and digest **types** must match Rq's. Handler::process receives `(transport_origin, request, oneshot<Response>)`; Monitor::collected receives `(transport_handler, response, count)`. Both callbacks are synchronous; they can hand work to the existing Executor owner. [Traits](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/collector/src/lib.rs#L22), [construction/start](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/collector/src/p2p/engine.rs#L62).

This fits optional request-bound signature solicitation, not unsolicited signature/certificate gossip. The engine tracks only peers accepted by the request sender for a commitment, accepts each requested transport peer once, and increments `count` **before** Monitor does application validation. An invalid application response can therefore occupy that peer's slot until explicit cancellation/reissue. Never interpret this count as f+1 validated original epoch signers. Executor independently checks subject, eligibility, signatures and identity once. A relay transport key does not become the original signer. Equal digest/commitment types do not enforce equal statement contents. [Tracking/send](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/collector/src/p2p/engine.rs#L141), [response/count](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/collector/src/p2p/engine.rs#L207).

Collector has no resolver fetch timeout/retry loop in this implementation. Outstanding commitments remain until Originator::cancel; handlers' pending oneshot responses occupy an unbounded futures Pool. Do not silently prescribe solicitation, retry schedules or count semantics through this optional reuse. It is not required for the minimal typed push path. [Cancel contract](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/collector/src/lib.rs#L35), [pool/run](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/collector/src/p2p/engine.rs#L103).

## Actual native assembly reference

The reshare validator registers raw authenticated channels (native two-argument register), constructs buffered Engine/mailbox, and starts an independent QMDB P2P Actor with database=None; its Source mailbox is passed into Stateful synchronization. It also starts the DKG actor on an existing raw channel. This supplies a concrete network/buffer/QMDB handle graph; Baton can reuse those lower-level pieces without adopting the example's Simplex/Stateful/DKG/quota defaults. [Channel allocation](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/examples/reshare/src/validator.rs#L86), [broadcast](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/examples/reshare/src/validator.rs#L138), [DB P2P](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/examples/reshare/src/validator.rs#L233), [Source injection](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/examples/reshare/src/validator.rs#L299).

DKG's existing application receive loop decodes peer bytes and verifies a signed acknowledgment via its application player/dealer logic before accepting it. The raw message sender remains explicit throughout; transport authentication alone is not the acknowledgment proof. This is an assembly pattern, **not** a direction/execution ACK proposal. Its Muxer and DKG actor are not needed merely to receive Baton's result signatures. ## Lifetime, verification and full-wire obligations

Network pairs/mailboxes/task handles/cache subscriptions/in-flight fetches are transient process resources. Storage retains canonical checkpoint, outputs, certificate/material availability linkage and direct/imported provenance under the existing recovery contract. Existing buffered caches and successful transport feedback do not establish durability; generic resolver shutdown drains active validation/serving, without persisting those queues. Start existing services under runtime supervision, preserve first-active-send network/body binding, and do not cancel the canonical mutation future to follow an advisory result update. No new supervisor or global startup ACK is required. [Resolver shutdown](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/resolver/src/p2p/engine.rs#L193), [handle ownership](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/runtime/src/utils/handle.rs#L26).

Keep executing while certificate/material is absent. Before stopping direct work, validate exact irrevocable input and full statement, f+1 eligible distinct original signatures, and applicable material for the selected canonical base. Imported material cannot produce an own DirectExecuted signature for that same range. Relay the original certificate; future direct work may sign its own range. None of the upstream cache/request/feedback APIs proves this ordering or writer/fence/recovery linkage.

Bound the complete selected message: typed push includes its full versioned subject/signature/certificate/material envelope; resolver Request is u64 request ID + payload tag + encoded key; Response is u64 ID + tag + Bytes length encoding + value. A key is **not** repeated in the wire Response. Check encoded proof/ops/material bytes and envelope overhead against the existing sender's maximum payload; max_serve_ops or signature count alone is not a byte bound. Keep decode/roster/proof/output/subscriber admission contextual. Budgets and codecs remain undecided. [Resolver EncodeSize/framing](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/resolver/src/p2p/wire.rs#L16), [DB serve count](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/glue/src/stateful/db/p2p/actor.rs#L342).
