# Wave 9 — deterministic runtime and simulated P2P assembly

Source/API audit by `/root/reuse_network_v3`. No runtime, test, native protocol, benchmark, or application implementation was executed. Canonical documentation is unchanged by this agent. The current verification page describes planned cases but does not yet identify the existing runtime/network harness they can use.

## Useful new connection

**Baton can assemble future E2E tests over the same public Sender/Receiver interfaces as deployment, using Commonware's existing deterministic runtime and simulated P2P.** Native Multimmit already has a public, feature-gated complete-engine cluster fixture. Its hardcoded mock application is a useful native-consensus fixture, rather than a complete transaction/body/order/execution/Storage test. Tempo provides an actual chain assembly reference which connects simulated consensus channels to a real, separately running execution node.

### Exact public construction and handle flow

| Public existing API at the native pin | Returned handle / input | What the future Baton assembly must connect |
|---|---|---|
| `deterministic::Runner::new(Config)` / `Runner::seeded(seed)`; `Runner::start` trait | `deterministic::Context` enters the root closure; implements runtime services | Give each retained service/node its child context and unique storage partition identity. Choose the scenario seed/timing/fault settings; this report adopts no values. |
| `simulated::Network::<E,P>::new_with_peers(context, Config, peers).await` | `(Network<E,P>, Oracle<P,E>)`; network context requires `Network + Spawner + Rng + Clock + Metrics` | Track the intended peer set. This convenience tracks set ID 0. Retain the network task ownership from `network.start() -> Handle<()>`. |
| `oracle.control(identity).register(channel, quota).await` | `Result<(simulated::Sender<P,E>, simulated::Receiver<P>), Error>` | Allocate separate native/application channels in the same graph. Native `Engine::start` consumes **four** `(Sender,Receiver)` tuples: data, consensus, certificates, resolver. Its data tuple transports native header traffic, not the application's full-body attachment. |
| `oracle.manager()` / `oracle.socket_manager()` / `oracle.control(identity)` | Existing `Provider + Manager`, `Provider + AddressableManager`, and `Blocker` implementations | Supply the body buffer/resolver/epoch manager/native blocker their existing interfaces; no extra peer-provider or simulator actor is needed. Peer tracking is not result-signing authority or a readiness predicate. |
| `oracle.add_link(from,to,Link)` / `remove_link` / `limit_bandwidth` | Async local topology controls | Link is **directed**; `latency` is mean latency, `jitter` standard deviation and native `success_rate` is `f64`. Explicitly create/remove each direction required by the scenario. No default bandwidth/loss/quota is selected. |

Native registration here takes **two** arguments, unlike stale three-argument authenticated discovery calls in `examples/log-multimmit`. Do not copy those stale calls into a simulated setup. The common application/native sender and receiver traits are the reuse boundary; constructing a simulated network does not exercise deployment's discovery/authenticated handshake implementation. The provider objects above are test substitutes for discovery/lookup. [Public simulated exports](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/p2p/src/simulated/mod.rs#L177), [mock discovery/lookup boundary](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/p2p/src/simulated/ingress.rs#L302).

The minimal remaining assembly work is application binding: real TxPool admission/selection; the existing body archive/buffer/generic resolver and native Automaton/Relay custody adapter; authenticated exact Orderer delivery; Executor's direct/imported result and worker control; and Storage's prepare/apply/recovery receipts. Run those existing components on these channel/runtime handles rather than writing a new transport or simulator. Body lookup must already work during native `Engine::start` recovery, per the existing startup page; simulated topology readiness does not replace that local dependency. No report, direction, result-certificate, or new peer ACK barrier is added.

## Native complete-engine fixture: public, but application-specific

`commonware_consensus::multimmit::mocks` is exported under `cfg(any(test, feature="mocks"))`; `mocks::cluster` is public on non-wasm targets. This is not limited to a private in-crate `#[cfg(test)]` module. `Committee<V>` exposes deterministic real fixture key material/config/signers/verifier. Public `cluster::start_network` also returns the existing Oracle, so a future test can reuse that network setup helper directly without selecting the complete mock Cluster. Fixture keys/namespaces/genesis remain test material. [Feature boundary](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/mod.rs#L229), [cluster export and Committee](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/mocks/mod.rs#L7), [existing start_network helper](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/mocks/cluster.rs#L1164).

`Cluster::<V>::new/new_with_producers` builds the committee and network; `launch` registers four planes; `launch_with` accepts caller-supplied native transports. `start_all`, `await_ready`, `partition/heal`, `set_directed_success_rate`, `produce_once/every`, `inspect`, `crash/restart` and finality observation are reusable **native test support**. Production engine actors and journal storage run, but `MockEngineConfig<V>` fixes Automaton/Relay to `MockApplication`, Reporter to `NoopReporter`, and crypto strategy to Sequential. `launch_with` changes transports/signing slot, not application/reporter generic parameters. Several extra operations such as per-plane blocking and checkpoint tuning remain `#[cfg(test)]` only. [Fixed config type](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/mocks/cluster.rs#L65), [construction](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/mocks/cluster.rs#L240), [transport and real engine wiring](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/mocks/cluster.rs#L458).

The mock builds a context-bound digest from synthetic payload text, records requests, returns a configured verification response (true by default), and its Relay returns local `Feedback::Ok` without sending a full body. It neither proves body/parent custody nor exercises TxPool, external exact Orderer, Executor, result material, QMDB root, or durable application delivery. For the real future Baton E2E, use public `Engine::new` with real adapters over the public simulated network; the fixed Cluster alone cannot substitute those responsibilities. [Mock verification/Relay](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/mocks/attached.rs#L302), [native existing integration scenario](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/tests.rs#L53).

`Cluster::crash` aborts/joins an engine while the enclosing deterministic runtime, network and other nodes remain alive; restart re-registers its planes under the existing identity and reopens its storage slot. This is distinct from discarding the entire runtime's volatile state. Its existing cfg(test) task-count assertions are fixture code, not an executed Baton quiescence or durable-state proof. [Per-engine crash/restart](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/mocks/cluster.rs#L679).

## Actual Tempo chain reference and determinism limits

Tempo's **public workspace E2E support** `setup_validators` creates `simulated::Network`, starts it, constructs validator configs and launches an `ExecutionRuntime`; `TestingNode` initializes the actual consensus engine and registers vote/certificate/resolver/body-broadcast/Marshal/DKG channels before `engine.start`. This demonstrates composition of existing channel handles, real body/Marshal consensus assembly, and a chain execution node. It is Tempo's Simplex/Reth application assembly, not a native Multimmit or Baton harness ready for direct import. Its Cargo graph uses registry Commonware 2026.9.0 and must not be mixed silently with the pinned native graph. [Actual setup](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/e2e/src/lib.rs#L247), [actual channel wiring](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/e2e/src/testing_node.rs#L352), [registry graph](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/Cargo.toml#L258).

`run` seeds the deterministic runtime, starts validators, waits on chain metrics, and returns `context.auditor().state()`. Returning that audit digest is not itself comparing two runs, verifying application state, or proving an invariant. The real execution runtime owns another OS thread and Tokio runtime plus actual databases; its Commonware runtime dependency enables `external`. In contrast, Tempo Executor's `pub(super)` test harness uses FakeExecution/FakeMarshal and some actor tests route through private stub transport, so neither is a public end-to-end Baton implementation. [Seeded E2E run](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/e2e/src/lib.rs#L345), [separate execution runtime](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/e2e/src/execution_runtime.rs#L322), [external feature](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/e2e/Cargo.toml#L36), [private Executor harness](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/consensus/src/executor/actor/tests/harness.rs#L1113).

Public `Runner::start_and_recover` returns an opaque runtime `Checkpoint`, consumable by `Runner::from(checkpoint)`. It retains the runtime's synced storage and other supported runtime state, while recovery reconstructs task/network/shutdown state and discards pending tasks, unsynced storage and network connections. It is not a Baton branch checkpoint, authenticated history interpretation, application cursor/provenance schema, or a durable filesystem image. Existing application stores must be reopened and linked under their own contracts. [Runtime recovery scope](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/runtime/src/deterministic.rs#L493), [recovery reconstruction](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/runtime/src/deterministic.rs#L1005).

Within the simulated runtime graph, a fixed seed can reproduce runtime scheduling/network events. Native deterministic Context's **existing `Strategizer::strategy` runs Rayon inline on the executor thread**, even though planning parallelism may differ. That is a concrete reusable worker-test strategy, distinct from constructing a background Rayon pool. Externally spawned VM/Rayon/Tokio work, real filesystem I/O, and unpaced future completions do not inherit determinism from simulated P2P. The runtime's `external` feature and `Pacer` can constrain future resolution time when the outside system is appropriately deterministic; Pacer may block and cannot safely wait on work requiring the same current thread. This does not prove that any particular Tempo/Baton external path is fully paced or deterministic. [Deterministic Rayon strategy](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/runtime/src/deterministic.rs#L1233), [external runtime scope](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/runtime/src/deterministic.rs#L7), [Pacer contract](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/runtime/src/lib.rs#L815).
