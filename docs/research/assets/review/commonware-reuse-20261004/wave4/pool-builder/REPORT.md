# Pool → producer body recipe: exact interfaces and completion

**Reuse one selected backend as the pool owner. The native producer attachment asks that owner for candidates, packs and retains the exact body, and completes the existing Automaton callback.** Static Features/Decision, native producer-context binding and durable Executor-outcome conversion are the application seams. No inspected backend provides an unchanged native Multimmit lifecycle.

This is a source audit and proposed integration recipe. It selects no backend, transaction semantics, routing/filter policy, queue ordering or storage layout. No protocol implementation, compilation or runtime validation was performed. Only this review directory was changed. Current TxPool contracts and relevant canonical pages were read after AGENTS/README/handoff/paper/docs context. Preserve the current five application traits and existing Automaton/Relay body callbacks; there is no need for another generic pool owner or application block-builder trait.

### Nunchi ingress has one important hook boundary

`start_p2p` takes the existing Commonware Sender/Receiver and directly decodes/checks/adopts peer transactions inside the actor; successful remote admissions are not rebroadcast. Public `submit` has no source argument and, when using that P2P actor, successful submissions always take the local gossip branch. Therefore do not implement a separate peer receiver by calling `submit` and describe it as preserving the actor's existing peer behavior. Nor assume a wrapper's `admit/analyze/classify` methods automatically see built-in P2P admissions. If policy acts only at packing, selected txs already reach application analysis. If admission routing/filtering is chosen, expose/connect the existing admission path or another chosen bounded ingress seam rather than a second candidate queue. This leaves filtering placement undecided. [Actor P2P boundary](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/actor.rs#L287), [local gossip](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/actor.rs#L433), [direct peer admission](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/actor.rs#L473).

The transport bounds remain necessary: built-in T requires `Encode + Read<Cfg=()>`; decode precedes stateless verification/encoded size checking, and that receiver does not explicitly reject unread trailing bytes. A custom payload decoder must bound allocations/nested counts before admission checks; selected ingress must validate a whole frame where required. `submit_many` has no aggregate Vec/work/byte limit itself. These are adapter/codec boundary checks, not an excuse to replace the working queue. [Bounds](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/actor.rs#L292), [batch submission](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/actor.rs#L94).

## 2. Nonce eligibility, packing and duplicate execution

**Pool eligibility is against maintained canonical state; native producer Context names a producer-chain parent. Those are different contexts.** Native spawn_build builds Context from protocol epoch, producer chain, next producer height and parent header digest. It retains job ID/generation/parent privately for callback correlation. Do not invent a public build-ID field, leader view or canonical execution parent from that Context. Preserve its supplied producer parent when packing a body. [Native correlation](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/actors/voter/executor.rs#L682).

Nunchi `pending(limit)` uses each lane's committed nonce and clones available contiguous entries; it updates a round-robin cursor but does not pop/reserve them. It is count-based and cannot promise that its whole output fits a byte bound or succeeds against a selected speculative/canonical runtime state. The public pending handle returns an empty Vec on shutdown as well as an empty ready pool; the adapter cannot interpret every empty response as healthy pool readiness. The source comment saying every result can apply is stronger than the actual nonce-only eligibility check: balance and other runtime predicates are not checked here. [Selection implementation](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/pool.rs#L157).

Treat Batch as an **ordered candidate sequence where backend dependencies matter**, not a mathematical set. If the chosen static filter or byte packer excludes nonce k, including k+1 from that lane can break the ready run. A prefix-preserving lane exclusion or another explicitly chosen dependency-aware selection policy is required; this report does not choose which. Multiple `pending` refills may return the same candidates because no entry is removed; bound work and keep per-build selected IDs/correlation rather than assume each refill drains fresh entries. An admission arriving concurrently can replace a same-nonce entry, while the already cloned tx/body remains the exact selected material. Do not look it up afresh by lane/nonce and silently alter a signed body. [Replacement](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/pool.rs#L108).

Reth's existing `BestTransactions::mark_invalid` prevents subsequent iterator dependencies after a capacity/selection exclusion; it is not global pool deletion. `no_updates` avoids unbounded new admissions entering an iteration, but does not freeze provider state or atomically bind eligibility to native Context. Tempo invokes dependency invalidation for gas capacity; its execution builder also feeds execution results into its iterator. Reuse the selected backend's existing dependency iterator, not the REVM/result-dependent builder for rootless body construction. [Iterator contract](https://github.com/paradigmxyz/reth/blob/038edab20dfff017f7a7502e683c732e5628ad89/crates/transaction-pool/src/traits.rs#L1109), [Tempo capacity exclusion](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/payload/builder/src/lib.rs#L578), [execution feedback](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/payload/builder/src/lib.rs#L650).

Constantinople accounts encoded signed tx bytes through `filled`, excludes final body framing, pops whole FIFO entries and stops on an oversized front batch. Returned candidates require the selected full body/framing check. Its non-retiring TxPool selection semantics require reconciliation; don't fix this by creating a second anonymous pool alongside it. [Destructive byte selection](https://github.com/commonwarexyz/constantinople/blob/3b6c92e76bf582855615844a4175b8304808f6a9/crates/mempool/src/webserver/actor.rs#L402).

Pool-local duplicate suppression and canonical replay are separate. Nunchi only checks its current digest index; finalized digests leave that index, and same-nonce replacement is independent. Several producer lanes can include identical txs even with perfectly working local dedup. No pool API here adopts whether repeated canonical txs are rejected, skipped or another application outcome. Executor's actual exact-order results provide that selected semantics; TxPool cleanup cannot infer execution success, next nonce or retirement from native body inclusion alone. In particular do not copy Nunchi chain's `max(included nonce + 1)` mapping unless those application semantics are separately chosen and valid for all outcomes/imports. [Dedup](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/pool.rs#L95), [SDK-specific finalized mapping](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/chain/src/application.rs#L896).

## 3. Canonical refresh, lost notifications and restart

Nunchi supplies `finalized(digests, lane_nonces, height) -> ()`, using `try_send`. When processed, Pool::finalize removes matching queued digests, records in-memory statuses, advances supplied nonces monotonically, removes newly stale entries and performs height-driven TTL scans. `Pool` itself is in a private module; its apparently public methods are not public crate imports. The exported handle offers no reliable commit send, processed canonical watermark/nonce read or explicit recovery seed API. This limits what an unchanged external wrapper can promise. [Lossy public notification](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/actor.rs#L195), [Processing](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/actor.rs#L414), [Private export boundary](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/lib.rs#L15).

Minimal required integration is an explicit completion contract: either on_commit acknowledges owner-retained work awaiting reconciliation, or expose/adapt reliable send + processed readiness through the existing actor. The first is not processed backend completion; the latter is new narrow integration. In either case, lost/reordered/duplicate outcome handling and selection readiness must connect to recoverable durable Executor/Storage results. Neither completion means durable admission, and no pool completion gates native cut/direction/Orderer delivery ACK. A call followed by pending/status cannot prove that a dropped empty-digest nonce snapshot was processed, because the public handle has no nonce/watermark query.

A lost lane-A refresh is not healed by later B-only updates. New pools start with empty committed_nonces, and unknown lanes default to nonce zero. Sending an authoritative snapshot through finalized can seed the same maintenance machinery if processed, but the unchanged public call does not certify startup readiness. Record/hydrate the relevant canonical nonce snapshot before ready selection; transaction retention/admission durability/status history are independently open. Status is expressly in-memory and capacity-evicted. The actor height drives TTL/status, so converting a durable execution range to that scalar needs the selected canonical mapping; native per-producer height is not automatically global canonical progress. Nonce advancement is monotone, but replayed older finalization can overwrite a status height, so monotonic nonce checks alone do not supply a fully ordered outcome-replay contract. [Initialization](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/pool.rs#L46), [Monotone refresh](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/pool.rs#L237), [Status contract](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/actor.rs#L217).

For a selected complete Ethereum stack, **Reth already has provider-backed maintenance**, not just pruning: `maintain_transaction_pool[_future]` initializes the pool tip, consumes canonical state notifications, reloads dirty accounts in chunks, detects discontinuous/deep updates and marks drift. Reuse this machinery with the actual compatible canonical provider/notification types instead of proposing another generic snapshot reconciler. It does not supply an unconditional lost-event/crash guarantee: initialization header lookup may fail, reloads are asynchronous, the task ends on an ended stream, and first-event/discontinuity correction depends on receiving the corresponding event. `CanonicalStateUpdate` expects the range to extend the pool's known tip. The adapter must still validate durable linked outcome conversion and completion meaning. [Public maintenance bounds/startup](https://github.com/paradigmxyz/reth/blob/038edab20dfff017f7a7502e683c732e5628ad89/crates/transaction-pool/src/maintain.rs#L98), [Dirty reload](https://github.com/paradigmxyz/reth/blob/038edab20dfff017f7a7502e683c732e5628ad89/crates/transaction-pool/src/maintain.rs#L191), [First event](https://github.com/paradigmxyz/reth/blob/038edab20dfff017f7a7502e683c732e5628ad89/crates/transaction-pool/src/maintain.rs#L260), [Canonical discontinuity](https://github.com/paradigmxyz/reth/blob/038edab20dfff017f7a7502e683c732e5628ad89/crates/transaction-pool/src/maintain.rs#L491).

Reth also exports `backup_local_transactions_task` for configured boot reinsertion and saving local txs at graceful shutdown. It is not per-admission write-ahead durability or crash recovery; the save occurs after graceful shutdown, and reinsertion outcomes are not an admission-durability guarantee. Assess that existing task before writing an equivalent local-tx shutdown backup. [Backup task](https://github.com/paradigmxyz/reth/blob/038edab20dfff017f7a7502e683c732e5628ad89/crates/transaction-pool/src/maintain.rs#L828).

If the whole Tempo extension is chosen, `TempoPool::on_canonical_state_change` delegates protocol-pool refresh and AA base fee only. Its **separate maintain_tempo_pool** drives canonical bundle-state AA 2D nonce refresh and AMM/keychain/token policies. Reusing only the wrapper's canonical method is not the full Tempo maintenance composition. Do not import those application policies merely to get its pool. [Wrapper refresh](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/transaction-pool/src/tempo_pool.rs#L1323), [Separate 2D maintenance](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/transaction-pool/src/maintain.rs#L476).

## 4. Minimal producer / body assembly without execution-dependent builders

1. Use existing `Automaton::propose(Context)` as the native request boundary; preserve producer parent/context in attachment-local ownership. Select from the one chosen pool via TxPool::select.
2. Apply chosen payload-only analysis/filtering and dependency rules, selected count/work limits, complete body encoding and fetch-envelope size. Build one exact immutable body; bind selected tx IDs, body commitment and producer header identity without treating them as interchangeable.
3. Put/sync exact body and required parent custody using the already documented archive owner, then resolve the existing digest receiver. No execution or Merkleized state is needed for this body recipe; any execution-aware application checks belong to the separately chosen execution contract.
4. Native consensus signs its header under native authority. Existing `Relay::broadcast(digest, ())` asks the attachment publication owner to load retained bytes and call existing `buffered::Mailbox::broadcast_shared`; local Feedback does not acknowledge peer receipt.
5. A canceled local build/subscriber calls on_proposal for its local correlation outcome; it does not delete canonically, roll back archive custody or imply the native private job completed. A non-destructive selected backend needs no generic unselect/reinsert engine solely for candidate cancellation.
6. Receiving `Automaton::verify(Context, payload)` uses existing buffer/resolver/archive and selected bounded decode/structural checks, then covering custody before true. Pool nonce eligibility and execution success do not become DA verdicts. Missing bytes stay pending.
7. Actual durable canonical Executor outcomes call TxPool::on_commit through the selected completion/reconciliation seam, including locally applied certified imports. This is independent of StoredBody, Reporter ProtocolAccepted, native publication and native ordering finality alone.

Existing callback reuse is [Automaton](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/lib.rs#L146), [Relay](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/lib.rs#L228), [buffered mailbox](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/broadcast/src/buffered/ingress.rs#L89). This does not settle native cut/prefix adoption, root-deferred storage or ordered delivery proofs.

Do not pull in a full chain builder to get the mempool: Nunchi's Stateful Application executes and merkleizes proposals; Constantinople's lifecycle executes/filters/refills and returns Merkleized batches; Tempo's application subscribes to an Executor-owned EVM payload job. Their subscriber ownership patterns are useful, but their chain semantics and proposal roots differ from this native body assembly. [Nunchi builder](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/chain/src/application.rs#L736), [Constantinople lifecycle](https://github.com/commonwarexyz/constantinople/blob/3b6c92e76bf582855615844a4175b8304808f6a9/crates/application/src/consensus/lifecycle.rs#L71), [Tempo ownership pattern](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/consensus/src/consensus/application/impl.rs#L206).
