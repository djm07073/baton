\begin{abstract}
Autobahn separates parallel block dissemination across producer lanes from consensus on cuts selecting lane prefixes. Application execution performed after ordering finality nevertheless remains on the critical path to state finalization. We propose Overpass, an extension for Autobahn-family consensus combining pipelined execution with operation-aware producer placement. Overpass applies a common ordering rule as blocks arrive, allowing speculative execution to overlap dissemination and ordering consensus. Once the canonical ordered prefix is known, valid work is retained and invalidated transactions are re-executed. Late-arriving predecessors and candidate changes can erode the latency benefit of starting early. To address this follow-on problem, Overpass uses declared state accesses and operation types to guide multilevel grouping and whole-transaction producer assignment, aiming to reduce cross-producer order-sensitive relationships without partitioning state ownership. We define the design over a common ordered-prefix contract and select Multimmit as the implementation and evaluation target, retaining its native voting and ordering rules. The planned evaluation compares post-order execution, pipelined execution, and pipelined execution with placement on the same Multimmit backend. It measures ingress-to-state-finalization latency, residual execution, and placement overhead rather than treating an earlier start as a demonstrated improvement.
\end{abstract}
