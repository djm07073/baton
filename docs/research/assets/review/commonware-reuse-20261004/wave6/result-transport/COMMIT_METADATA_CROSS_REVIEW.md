## Exact checks against fresh source

1. **Metadata atomicity is local to that store.** The two CRC/versioned blobs preserve a complete atomic metadata copy; multiple pending entries are committed together, and put_sync syncs every pending change. Native Metadata writes have no connection to QMDB or journal transactions. The report and page correctly preserve a separately selected state/output/cursor/provenance recovery contract. CRC integrity is not native-order or execution evidence. [Atomic store](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/storage/src/metadata/mod.rs#L1), [put/put_sync](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/storage/src/metadata/storage.rs#L683).
2. **Observer drop and cancellation are distinct.** start_sync stores a shared completion internally and returns a completion observer. The next sync awaits that retained completion before writing; a deferred failure returns error without another write and destroys the consuming handle. Dropping the observer does not cancel disk sync. In contrast, dropping the consuming Metadata sync/start_sync Future loses its store handle; Shared mutation interrupted before put loses the shared DB cell. The report does not promise rollback or ordinary cloned-handle retry. [Pending error guard](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/storage/src/metadata/storage.rs#L382), [completion retention](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/storage/src/metadata/storage.rs#L600), [public consuming/observer contract](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/storage/src/metadata/storage.rs#L616), [start_sync](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/storage/src/metadata/storage.rs#L742), [Shared](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/glue/src/stateful/db/mod.rs#L112).
3. **Tuple finalize/barrier is not cross-store atomic commit.** Tuple finalize joins individually locked member operations, restores each Shared cell after successful mutation and returns their flush handles. Immediate failure is fatal because other members may have advanced. Barrier joins all covering flushes; Closed/Aborted returns false, any other deferred failure panics. No tuple rollback follows. The table and adjacent existing failure table preserve these distinctions. [Tuple finalize](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/glue/src/stateful/db/mod.rs#L998), [fatal mutation](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/glue/src/stateful/db/mod.rs#L1783), [Barrier](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/glue/src/stateful/db/mod.rs#L425).
4. **Journal append is not durable application completion.** The variable journal exposes existing append, sync/start_sync, read/replay, with consuming handle ownership. A successful covering start_sync observer guarantees prior appended state durability, while sync additionally supplies the current recovery watermark. The reader table intentionally says append/sync and requires exact record/durability/retention; it does not invent an authenticated output schema or claim append alone is commit. [Append](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/storage/src/journal/contiguous/variable.rs#L2267), [start_sync guarantee](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/storage/src/journal/contiguous/variable.rs#L2350).

Baton exact dense cursor/outputs/provenance linkage remains an application obligation. [Native new-applied completion](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/glue/src/stateful/actor/core/processing.rs#L307).
