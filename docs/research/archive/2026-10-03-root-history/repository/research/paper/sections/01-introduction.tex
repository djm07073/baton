\section{Introduction}
\label{sec:introduction}

This work targets end-to-end latency from transaction ingress to certified application-state finalization. Applications such as transfers and multi-account updates need not only a decision about which inputs are selected, but also their final effects. We distinguish ordering finality, certification of execution results, and the readiness of a particular node to serve durably applied state. The interval from cut finality to certified results is the principal optimization target within that end-to-end path. A reduction in this interval is insufficient if producer assignment, queueing, or ordering delays increase total latency. Durable read readiness is a separate, potentially later completion event.

Autobahn's multi-producer dissemination makes executable data available before the final cut. Autobahn already uses deterministic zipping to order selected blocks. We use \emph{Autobahn-family} as a design category covering parallel producer-chain dissemination coupled to consensus-derived global ordering, including Autobahn and Multimmit; it does not denote identical voting protocols. Our starting point is the early application of the selected protocol's ordering rule, not the invention of determinism. We define Overpass at this family level and select Multimmit as the concrete implementation and evaluation target. \citep{autobahn,multimmit}

We apply the common ordering rule before finality to pipeline consensus and application execution for the same candidate interval. Producer and validator tasks can concurrently disseminate blocks, receive and vote, synchronize missing data, update candidate orders, and execute transactions. Not every voter must possess the same data or speculative plan. Only computations valid for the actual emitted canonical prefix and parent may be adopted. The design changes execution timing, producer placement, and their connection to ordering finality; it does not introduce a new execution engine or replace native BFT voting.

Re-execution can erase the gains from starting early. If a writer that precedes a reader in the final reference order arrives late, the reader's previous observation may become invalid. Correcting that result is necessary for safety, but repeated invalidation and resource contention can increase the work remaining after the cut. An earlier execution start does not, by itself, establish a latency improvement.

\reviewnote{EXPERIMENT NEEDED E1}{The frequency and magnitude of this effect remain unmeasured. Vary load, late-predecessor frequency, and contention, and jointly measure execution head start, discarded work, post-cut re-execution time, and submission-to-result latency.}

We address this follow-on problem with operation-aware producer placement. Enforced state-access declarations and shared finalized history guide a deterministic multilevel search that groups related inputs while accounting for producer load and reassignment cost. Producers use the resulting common map to route whole transactions, without partitioning state ownership. Section~\ref{sec:placement} defines the search and cut-controlled map updates; their latency benefit remains an evaluation question.

Final results require native ordering finality and \(f+1\) matching direct-execution signatures for the exact ordered prefix, canonical parent, runtime, and complete result. At most f Byzantine validators imply at least one honest direct executor among these signers. Native ordering quorums are inherited, not replaced by this threshold. The family model parameterizes signer eligibility; the previous Autobahn-specific voter-subset policy is not imported into Multimmit without a separate decision. Cut voters need not have completed execution, and lagging nodes may verify and apply certified updates. \citep{pbft}

The proposed contributions are an Autobahn-family execution pipeline, operation-aware producer placement intended to preserve its gains under late-predecessor invalidation, and an analysis of their correctness and performance conditions. Evaluation centers on Original, Pipeline, and Pipeline + Placement, all instantiated on Multimmit with the same application and execution backend. Results on that artifact will not establish measured gains on Autobahn itself. Access declarations, multilevel search, determinism, the \(f+1\) threshold, and state transfer are not independent novelty claims.

Section~\ref{sec:design} first presents the core pipeline, safe result reuse, and certified state installation. Section~\ref{sec:placement} then explains how re-execution can consume its gains and develops grouping and enforced producer placement. The correctness and evaluation sections examine both mechanisms and their interaction.
