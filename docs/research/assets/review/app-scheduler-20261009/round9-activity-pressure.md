# Round 9: Activity ingress, queue pressure and callback failures

Inspected current source `6233438985d8249d2b2bc1204191d5d405652288`, 2026-10-09. Source audit only: no native changes, new reliability layer or runtime tests.

## Findings

Engine does not retry Reporter delivery: `actors/voter/actor/live.rs:384–414` calls `let _ = self.reporter.report(activity)`. Activity is explicitly best-effort/idempotent, not a protocol-progress acknowledgement (`types/activity.rs:58–64`). However, the supplied Marshal mailbox has event-specific pressure handling that a generic lossy App forwarding queue would erase. The intended assembly already sends to Marshal directly and an optional App observer as a sibling (`examples/log-multimmit/src/node.rs:318`; `consensus/src/reporter.rs:31–55`). Both siblings are called; their worst feedback is combined, then ignored by Engine. Reporters must return promptly because they run synchronously in that call path.

Neither Feedback::Ok nor Backoff is a durable event receipt. Policy-controlled actor mailboxes return Backoff when their overflow handler handles an item, including policies that intentionally drop optional hints (`actor/src/mailbox.rs:169–213`). Closed cannot itself make Engine stop: the existing node owner must observe service completion and coordinate sibling lifetimes.

|---|---|---|
| CertificateRecorded | `marshal/mailbox.rs:500–510` bypasses router and calls catalog.release(chain, released). Catalog CursorMessage overflow coalesces releases by chain using max height and keeps them across cursor-reset barriers (`actors/catalog/mailbox.rs:365–405,799–804`). | This special release is not an ordinary lossy router hint. Queueing is still not disk completion; a closed catalog returns Closed. Missing a release conservatively retains more bodies. Engine re-reports each retained chain's current release at startup (`machine/reducer/step.rs:699–717`) and reports new ones after durable acknowledgement (`reducer/persistence.rs:610–627`). No need for an App retention-report retry service. |
| ProtocolAccepted(Lqc) | Router validates artifact id, stages the L-QC, then triggers synchronizer (`service/router.rs:235–267`). Router overflow keeps one L-QC hint of the highest view, independently of the finality-fact hint (`mailbox.rs:99–191`). | Synchronize overflow retains/coalesces proof batches, preferring the highest view and bounding distinct same-view proofs (`actors/synchronizer/mailbox.rs:82–120,152–173`). This is the essential progress target; exact backfill does not independently discover the latest finality frontier. Supplied wiring preserves this path under ordinary queue pressure, not every individual L-QC observation. |
| LeaderFinalized / LeaderFinalityUpdated | Router overflow keeps the richest fact ranked by view and vote count. Router forwards it to synchronizer (`service/router.rs:296–298`). | Synchronizer overflow may drop direct-pool Finality facts as optional acceleration (`actors/synchronizer/mailbox.rs:159–164`). These are not a guaranteed stream of every direct-pool advance. L-QC synchronization remains the native fallback; a later proof/history may expose further output. No immediate-latency promise follows for a dropped richer fact. |
| HistoryAccepted | Router checks the record commitment, stages it in catalog and notifies backfill (`service/router.rs:270–295`). | Ordinary router pressure can drop this peer-seeding hint. This repairs required material when available, not the original event stream. |
| ProtocolAccepted(TransactionBlock) | Router forwards authenticated header to synchronizer's header cache. | Router and synchronizer can drop the hint. Canonical producer ancestry/body resolution has exact fallback; the hint only saves later work. |
| ProtocolAccepted(DaCertificate) | Router forwards its header and calls backfill.certified_block(reference). | Both forwarding stages can drop optional hints. `backfill/mailbox.rs:128–149,401–411` states the certificate marker is opportunistic. A retained marker can turn an existing/later Wait subscription into a peer fetch. If the marker itself is dropped, do not promise that every later public subscribe initiates fetching; buffered/local admission or later independent certified/canonical fetch demand may complete it. |
| CommitmentsAccepted | Router forwards native selected paths to synchronizer. | Optional path-cache acceleration at both overflow stages. Does not prove body availability or replace exact fallback. |
| TransactionProposed | Router deliberately ignores it (`service/router.rs:231`). | Optional App observer may use the signed-local-body observation as speculative provenance. It is not a Marshal storage/finality action. Missing it may lose early work; canonical Update handling must still work. Retried native signing completion can report the same block, so observers must be idempotent. |
| Other ProtocolAccepted variants | No Marshal action in this router match. | Do not describe the native Activity feed as a comprehensive durable App event bus. |

The router ignores only catalog *rejections* of hint material; unexpected catalog errors stop its job and then the service (`service/router.rs:254–264,282–291`). Current staged L-QC/history admissions are buffered admissions: catalog parks intake when admission room is unavailable (`actors/catalog/admission.rs:460–474`), rather than using CommitWindowFull as their normal queue-pressure result. The generic is_rejected branch is not evidence that ordinary full commit slots silently discard valid L-QC staging.

## What recovery actually restores

- Marshal synchronizer reopens its durable checkpoint/history/frontiers, reads latest retained L-QC and resumes it when it differs from the selected floor (`actors/synchronizer/actor.rs:280–327`). Already durable output delivery has its separate ACK-cursor replay contract.
- Engine startup reports current per-chain release bounds and re-observes retained ready artifacts; `restore_ready_artifacts` rebuilds relevant native views/finality and calls push_acceptance (`machine/reducer/persistence.rs:630–656`; `reducer/step.rs:699–717`). This is retained-state reconstruction, not a persistent log of every Activity.
- Proof-driven synchronization fetches exact missing history, ancestry and bodies and applies the same native order. It requires a known progress target and available valid material. It cannot rescue an application that removed Marshal from the Reporter branch, nor guarantee an optional TransactionProposed or direct-finality callback is replayed.
- A crash can lose volatile buffered hint work before native/catalog recovery or later proof input restores useful state. This review makes no exactly-once or universal event-redelivery claim.

## Public custody pressure and errors

`ask_unreliable` maps an explicitly rejected enqueue to Busy, a closed endpoint/dropped reply to Closed, and waits after Ok/Backoff (`actors/util/ask.rs:22–34`). Public error conversion maps backfill PendingFull to Busy and backfill MailboxClosed to Closed; NetworkClosed remains Failed with its cause (`marshal/types.rs:178–240`). Therefore “all service errors mean invalid body” and “all transient failure is Busy” are both wrong.

| Public operation | Current pressure behavior | App response boundary |
|---|---|---|
| stage_block / put_block | Full router overflow rejects StageBlock; caller receives Busy. Router runs accepted work as its own job. stage returns a custody token after acceptance; put awaits durability. | Retry recoverable admission pressure only within the active request/lifecycle; do not return a proposal digest backed only by rejected staging. Once a digest was promised, its local verify must establish custody. Dropping an accepted token does not cancel storage. |
| fetch_block / fetch_certificate | Explicit requests use backfill registry. Pending-full requests can fail Busy; higher-priority native fetches may evict older waiters (`backfill/actor.rs:646–657`; `registry.rs:28–41,177–201`). | Resource pressure does not make referenced bytes permanently invalid. Do not treat fetched buffered material as durable custody. |
| subscribe_block | Shared subscription slots make callers wait before router submission; live subscriptions are retained in router overflow (`mailbox.rs:99–135,196–240,419–449`). | This protects the caller-slot bound; it is not a never-fails guarantee for acquisition/storage. The internal Wait backfill branch can fail PendingFull; the router then waits for the buffered branch before returning that error if neither supplies a block (`service/router.rs:341–375`). Successful return includes durable catalog admission. |
| Closed / Failed | Closed means a service endpoint stopped; Failed retains its component cause. Backfill NetworkClosed, invalid requests, or storage-adjacent failures are not a bool verdict. | Existing node lifecycle handles service failure/recovery. Failed mutable storage makes that instance unusable. Do not send true without successful custody, false for operational pressure, or repeatedly close verification as a retry protocol. |

The example verify handler logs subscription errors and drops the response (`examples/log-multimmit/src/application/actor.rs:79–102`). Current remote Multimmit may retry a closed receiver, but local closure is fatal and recovery closure fails open, as prior rounds documented. Copying this small demo error branch is not a general application retry design.

Existing Marshal Config capacities already derive the bounds: catalog_mailbox_size supplies router mailbox capacity; resolver_mailbox_size supplies router jobs, subscription caller slots and backfill pending capacity; configured backfill concurrency is checked and constrained by the byte budget (`marshal/config.rs:550–593`). Use those and bounded App workloads; do not add a replacement transport/reporter service.
