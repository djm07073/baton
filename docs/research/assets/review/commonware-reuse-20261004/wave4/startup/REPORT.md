# Startup, restart and lifecycle assembly audit

2026-10-04; reviewer `/root/reuse_network_v3`. Documentation baseline `cd9a0864cfa2171769bbe7f6d64fa3396ca878c6`. No canonical page, external checkout, dependency or protocol implementation was changed. This is fresh source/API inspection, not a native run or build.

## Result

**Reuse Commonware's archive initialization, task supervision and existing engine handles.** Baton needs exact custody/history/state bindings and lifecycle ownership, not another generic recovery runner or supervisor. The current startup page already preserves the important pre-running recovered-body fence and independent execution recovery. Three useful refinements remain: name the first-outbound network-binding dependency; separate remembered native readiness from ongoing lifecycle; and explain abort/shutdown versus storage durability.

There is also an implementation-proof limitation beneath the native documented `Running::join` contract. Retain the documented abort-then-join lifecycle; do not claim this source audit proved strict child/signing-material quiescence. No observed race or native bug is claimed.

## Concrete handle flow

1. **Register all logical pairs, then bind before their first outbound use.** Native `Network::start` binds registered senders synchronously before spawning its network task. A pre-binding submission returns accepted feedback while discarding the content. Actor construction, mailbox creation and even an idle actor start can precede binding safely; an active fetch or publication cannot rely on that feedback for delivery. [Start/binding](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/p2p/src/authenticated/discovery/network.rs#L192), [unbound send](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/p2p/src/authenticated/router/ingress.rs#L204).
2. **Open/reopen body archives using their existing initialization.** Native immutable Archive initialization uses Metadata's committed freezer checkpoint, reopens Freezer, and restores committed ordinal sections; it does not need a parallel Baton replay engine. Missing commit metadata means old freezer blobs are treated as uncommitted. Archive initialization is local storage recovery, not authentication of Baton's header/body/context mapping. Its indices and partition identity must remain correct. [Archive initialization](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/storage/src/archive/immutable/storage.rs#L110).
3. **Start public buffer and generic resolver independently of Native Running.** Their `start((Sender, Receiver))` returns a task Handle, with no separate `ready` API. Each subscribes to the existing peer Provider and performs its own typed wire handling. Connect archive-backed Producer and verifying Consumer before native callbacks can need them. In-memory buffer contents start empty; reconstruct required work from retained archives/application requests, not a promise of cache persistence. [Buffer construction/start](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/broadcast/src/buffered/engine.rs#L121), [resolver start](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/resolver/src/p2p/engine.rs#L151).
4. **Attach usable custody callbacks before invoking native Engine::start.** Native start opens/replays its own checkpoint/journal, verifies retained cryptographic artifacts, and then calls Automaton for each required recovered `(Context, commitment)` before constructing actors. These body requests cannot depend on receiving a Running handle or on Native Running's resolver being active: start has not returned yet. The separate generic body resolver breaks that initialization cycle. Callback false/closed becomes `RecoveredPayloadUnverified`; temporarily unavailable body dependencies can remain pending. [Pre-running body fence](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/engine.rs#L700), [bounded recovered verification](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/engine.rs#L272).
5. **Await native startup readiness, retaining lifecycle ownership.** After startup persistence drains, the voter seeds its native resolver, submits the initial producer wake and sends readiness. This does not await a newly proposed application's execution/root, its body propagation or an application result certificate. Recovery and exact-input delivery retain their independent conditions. [Voter readiness](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/actors/voter/actor.rs#L913).
6. **Reuse archive sync completion for exact body custody.** Immutable sync first synchronizes Freezer and Ordinal, then publishes their checkpoint through Metadata. `Archive::start_sync` covers accepted prior writes; the default path runs sync and returns an already-finished Handle. A fatal sync result invalidates the returned archive. Neither a task Handle nor a successful init substitutes for the exact covering sync required by the body verdict. [Immutable sync ordering](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/storage/src/archive/immutable/storage.rs#L293), [public sync contract](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/storage/src/archive/mod.rs#L137).

Executor/Storage recovery can proceed concurrently. Commonware archive recovery and native journal replay do not establish application state/output/AppliedCursor/provenance atomicity, external Orderer witness coverage or dense canonical emission.

## Existing supervision versus durable shutdown

| Existing API | Actual useful behavior | Application boundary that remains |
|---|---|---|
| `Supervisor::child`, `Spawner::spawn` | Descendant task ownership; parent completion/abort propagates cancellation | Choose the correct owner lifetime; do not place a canonical writer beneath an advisory worker that may exit |
| `Handle::select` | First owned handle completion aborts the whole group; dropping the selection future also aborts the group | Only group services with that teardown boundary; this is cancellation, not graceful flushing or automatic restart |
| `Spawner::stopped` / `stop` | Cooperative global shutdown signal; stop waits for held Signal references to be released | Hold cleanup ownership until required work finishes; absence of signal references is not proof every storage operation was flushed |
| `Running::ready`, `abort`, `join` | Native startup milestone and documented lifecycle ownership | Body/order/execution readiness, durable application completion and cross-service shutdown remain distinct |

These are public runtime APIs, not a new application trait. Native engine already supervises its mandatory voter/batcher/resolver; adding another generic supervisor inside it is unnecessary. [Spawner supervision and stop](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/runtime/src/lib.rs#L287), [owned Handle selection](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/runtime/src/utils/handle.rs#L189), [signal completion guard](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/runtime/src/utils/signal.rs#L125).

Resolver shutdown drains in-flight delivery/subscribers and cancels serving futures; buffer shutdown does not persist its cache. Neither closes/syncs a separate archive owner. Native voter shutdown cancels application/crypto jobs and correlations, not a whole-application commit transaction. Preserve Storage writer/fencing/recovery and separate custody mutation lifetime through actual completion. Exact cancellation semantics remain integration work; no timeout, quota or shutdown policy is selected. [Resolver cleanup](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/resolver/src/p2p/engine.rs#L193), [voter cleanup](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/actors/voter/executor.rs#L58).

`Running::ready` remembers Ready/Failed. Once true, another ready call remains true even if the engine subsequently exits; it is a completed startup milestone, not a health probe. The caller retains Running lifecycle and existing engine/service task handles. Inspector and Serve are useful queries, but their optional answers are not a combined health/custody certificate. [Readiness state](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/engine.rs#L514).

### Documented join and source-proof limitation

Native documentation says join waits for every engine child to stop, and its module describes joining as evidence of signing-material release. The public implementation only awaits the root task. That root selects a shutdown signal or first mandatory child exit, then returns without awaiting the other child handles. Runtime task completion sends its result before synchronously requesting descendant abort. The abort tree supplies cancellation requests; these source sections alone do not show every child future dropped before the root receiver resolves. [Native join contract/implementation](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/engine.rs#L588), [root exit](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/engine.rs#L816), [runtime notification then tree abort](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/runtime/src/utils/handle.rs#L129), [abort implementation](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/runtime/src/utils/supervision.rs#L145).

This is an **unproved strict quiescence postcondition in this inspection**, not an executed race or confirmed bug. Keep the upstream abort-then-join API recipe; do not infer a QMDB/archive flush barrier from it or use this report as proof that signing authority may safely be transferred solely because a root receiver resolved. Native integration/authority handoff needs independent closure. Cross-review identity and exact fresh-file receipts are recorded in [LIFECYCLE_CROSS_REVIEW.md](LIFECYCLE_CROSS_REVIEW.md).

## Actual chain assembly: what to copy

**Tempo separates initialization from task start.** It initializes recovered finalized stores/range and connects Executor/peer manager/buffer first. At its outer entry it starts Network before the consensus task; inside, peer manager, body broadcast and backfill bridge start before Marshal/epoch manager. Mandatory services are held in `Handle::select`, so even a clean exit terminates the group. Copy this handle/lifetime arrangement; its Marshal helper/Hybrid store remain Tempo-internal Simplex/Reth code. Do not copy them as public Multimmit wrappers. [Outer binding/start](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/consensus/src/lib.rs#L148), [service starts/selection](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/consensus/src/consensus/engine.rs#L524), [startup range reconciliation](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/consensus/src/alias.rs#L132).

**Alto opens immutable finalized archives before chain start, then starts body handling before consensus.** Its run method explicitly starts Marshal before consensus to avoid restart blocking on enqueued application events; optional queued-upload consumers also resume first. Its task collection uses `try_join_all`, which waits for all successful completions and returns early on error. The nearby “wait for any actor” comment must not be copied as a first-clean-exit guarantee; Tempo/native Handle selection has different behavior. [Archive init](https://github.com/commonwarexyz/alto/blob/1d87569348b5560699465a72d691d90f18affb9c/chain/src/engine.rs#L195), [actual startup/task wait](https://github.com/commonwarexyz/alto/blob/1d87569348b5560699465a72d691d90f18affb9c/chain/src/engine.rs#L465), [network first](https://github.com/commonwarexyz/alto/blob/1d87569348b5560699465a72d691d90f18affb9c/validator/src/main.rs#L349).

**Do not reset native safety storage by copying a Simplex recovery hint.** Tempo rejects a finalized-tip/archive versus Marshal metadata mismatch and its error string suggests deleting consensus storage. Native Multimmit explicitly cannot distinguish a first start from total storage loss under an active epoch key; its fresh path is permitted only for a never-active epoch key and new partition prefix. Preserve partition/key-use provenance; new committee/epoch startup is a deployment boundary. Existing native recovery reuses checkpoints/journal and verifies retained artifacts instead of an application-imported trusted checkpoint. [Tempo consistency check](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/consensus/src/alias.rs#L216), [native fresh/recovery restriction](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/engine.rs#L306).
