## Public native APIs and actual ownership

| Need | Existing public API | Remaining responsibility |
|---|---|---|
| Share one observed activity with two destinations | `Reporters::<A, R1, R2>::from((r1, r2))`; nested tuples through nested Reporters | Both implement Reporter with the same Activity; activity is Clone + Send + 'static; callbacks perform short local submission/context handling |
| Optional observation | Reporter implementation for `Option<R>` | None deliberately ignores the activity and returns Feedback::Ok; successful feedback does not prove a consumer exists |
| Compose local submission feedback | Reporters combines Closed before Backoff before Ok | Calls are synchronous; no spawned work, durable acknowledgement, automatic retry or per-destination failure isolation |
| Enqueue local typed work | `actor::mailbox::new(metrics, NonZeroUsize)` → cloneable Sender and owned Receiver; `Sender::enqueue` → Feedback | Message implements Policy; selected overflow/retention/admission behavior must fit its semantics |
| Explicitly reject overload | `mailbox::new_unreliable`; UnreliableSender::enqueue | Message implements UnreliablePolicy; caller handles Rejected and stale/local context appropriately |

Both present reporters are called for each report, with one activity clone. Nesting extends that composition. No thread/task separation follows: slow work or panic in a callback can affect subsequent dispatch. The activity types must genuinely agree; Reporters performs no schema conversion. An internal adapter maps native Activity to the application's header/body observation.

Ready capacity is bounded, but overflow retention is caller-managed. Native Policy can retain, coalesce or deliberately do no work for a satisfied/superseded message. Backoff means that policy handled overflow, not receiver processing or guaranteed retention of every original event. VecDeque already implements Overflow's ordered drain, but selecting unbounded FIFO retention is not a numeric memory limit. Policy runs under the overflow lock and must not re-enter the same mailbox or unwind after changing overflow. These are fitting-queue obligations, not a selected Baton policy. [Policy and constraints](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/actor/src/mailbox.rs#L58), [Policy semantics](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/actor/src/mailbox.rs#L91), [Feedback contract](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/actor/src/lib.rs#L13).

## Actual native and Tempo connections

Native Activity is Clone and stores an Arc of the exact contextually accepted artifact. Its documentation explicitly calls activities idempotent, non-authoritative telemetry: no delivery acknowledgement, retention authority or protocol progress permission. Native voter dispatch ignores Reporter feedback. Reporters can compose fitting opportunistic body-header intake and observers without another general distributor; neither fan-out nor mailbox acceptance creates the missing durable exact-source handoff. [Native Activity](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/types/activity.rs#L7), [Native dispatch](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/actors/voter/actor.rs#L1655).

Tempo nests existing Reporters around Executor, DKG, peer-manager, feed and optional gossip handles. Those handle implementations enqueue their own commands; the reused Reporters object does not implement their state machines. Executor and peer-manager ingress use unbounded futures mpsc at this source pin. Copy the composition pattern, not an unsupported bounded-memory claim or Tempo's private mailbox type/actor policy. Their Activity is Simplex Marshal Update<Block>, not native Multimmit Activity. [Tempo composition](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/consensus/src/consensus/engine.rs#L535), [Executor ingress](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/consensus/src/executor/ingress.rs#L20), [Peer-manager Reporter](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/consensus/src/peer_manager/ingress.rs#L148).
