## One precise surface correction

Canonical Rust `TxPool::select` currently says:

> Selection alone does not retire transactions from the pool.

Detailed pages correctly allow a conditionally adapted destructive backend with ownership/reselection reconciliation. A developer reading only the method comment can interpret it as forbidding any candidate-queue removal, making Constantinople seem incompatible on principle or motivating a parallel non-destructive pool. The intended requirement is that selection does not establish **canonical** retirement/outcomes. Replace that one comment with:

> Selection alone does not establish canonical retirement.

This adopts no destructive policy and authorizes no permanent loss. Existing detail still requires retained selected bytes, cancellation/reselection ownership, actual durable outcomes and backend reconciliation. No method, type, parameter or return signature changes.
