# Cases to verify

**Validation should exercise each responsibility at its failure boundary.** The plan covers normal flow, missing input, stale completion, cancellation, crashes, and recovery. These cases are planned, not executed test results.

**Assemble future E2E tests with Commonware's existing runtime, network and storage controls.** Use the same public Sender/Receiver interfaces as deployment, with simulated links controlling delivery. Attach the selected TxPool, body buffer/resolver/archive, native callbacks, Orderer, Executor and Storage; a second transport or crash simulator is unnecessary.

| Existing support | Responsibility in a future test | Connection still needed |
|---|---|---|
| `deterministic::Runner` + `simulated::Network/Oracle` | Seeded scheduling, peer/channel registration, directed loss/latency and bandwidth controls | Register native planes and separate body/result channels before use; simulated transport does not exercise deployment handshake/discovery |
| Native `multimmit::mocks::cluster::Cluster` | Existing engine/journal startup, partitions and per-engine restart | Public under the mocks feature on non-wasm, but fixes MockApplication and NoopReporter. For real custody and application E2E, attach actual callbacks to public `Engine::new` |
| `mocks::DelayedSyncContext` + `PendingSyncs` | Run the selected real QMDB while controlling flush progress/completion | Keep the same Storage writer and verify its complete state/output/cursor/provenance receipt before ACK or read readiness |

Native channel registration takes `register(channel, quota)`. The public Cluster's `launch_with` changes transports, not its application callbacks; its Relay sends no full body. `Cluster::crash` aborts one engine while the shared runtime/network remain alive. Reuse it for native scenarios, then use public Engine attachments for the application path. [Channel handles](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/p2p/src/simulated/ingress.rs#L428), [fixed Cluster configuration](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/mocks/cluster.rs#L65), [mock verification/Relay](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/mocks/attached.rs#L302), [per-engine restart](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/mocks/cluster.rs#L679), [public Engine attachments](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/engine.rs#L635).

**Control the failure boundary rather than sleeping and assuming it happened.** `PendingSyncs` controls `Blob::start_sync`: the default parks its completion future before inner sync; native `completion_delayed()` starts inner sync and gates observation of completion. Observe the gate and actual inner progress separately: starting sync alone does not prove durability. This permits unsynced restart and durable-but-unobserved completion cases. A lost delivery ACK is a separate case after the full application receipt is durable. Consume `Runner::start_and_recover`'s checkpoint in `Runner::from(checkpoint)` and reopen stores/services; neither live tasks nor old writer authority carry over. The panic path does not return a checkpoint. These controls model runtime storage, not arbitrary filesystem/device failure. `completion_delayed()` is absent from the inspected registry release; use the adopted native API. [Sync ordering and controls](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/runtime/src/mocks.rs#L633), [completion gate](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/runtime/src/mocks.rs#L749), [runtime recovery](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/runtime/src/deterministic.rs#L567).

**Copy real-chain assembly patterns, then assert Baton outcomes.** Tempo's E2E support wires simulated consensus channels to a separate execution runtime. Alto's chain fixture reopens a runtime checkpoint without relinking peers and checks durable queued-work replay. Use those shapes with public Commonware handles; Alto's private cfg(test) helpers and Simplex certificates are source examples. Comparing runtime `Auditor::state()` fingerprints checks trace repeatability; it does not assert exact order, custody, f+1 certification or linked application state. External VM/thread/I/O work does not automatically inherit deterministic scheduling. Keep each application assertion explicit and every case below **Not run** until that integration is actually executed. [Tempo setup](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/e2e/src/lib.rs#L247), [Tempo channel wiring](https://github.com/tempoxyz/tempo/blob/61c979a524f9af5de9c540a0088c429a44741e4c/crates/e2e/src/testing_node.rs#L352), [Alto replay fixture](https://github.com/commonwarexyz/alto/blob/1d87569348b5560699465a72d691d90f18affb9c/chain/src/lib.rs#L1317), [Alto recovery without relinking](https://github.com/commonwarexyz/alto/blob/1d87569348b5560699465a72d691d90f18affb9c/chain/src/lib.rs#L1487), [Auditor](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/runtime/src/deterministic.rs#L174), [external work boundary](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/runtime/src/deterministic.rs#L7).

## Verification cases by component

| Component | Cases to verify | Execution status |
|---|---|---|
| Tx / pool | New, duplicate, structurally invalid; proposal cancellation; no cleanup before canonical outcome | Not run |
| Builder / custody | Digest mismatch, missing body/parent, durability failure, late build completion | Not run |
| Native / delivery | Unresolved gap, authenticated empty, extension, missing history, preserved emitted prefix after restart | Not run |
| Leader Baton | Threshold/deadline race, duplicate identity, stale context, incomplete Baton planning, cut ready first | Not run |
| Non-leader Baton | Missed/late direction, missing body, order change, separated producer/executor roles | Not run |
| Execution | Prefix reuse, input-state/runtime mismatch, canceled-job completion, partial-prefix commit | Not run |
| Storage / QMDB | Sealed-parent forks vs rootless overlay; exact-prefix preparation; root/boundary determinism; valid-access fences through merkleize | Not run |
| QMDB recovery | Crash during commit, lost ACK, same-range redelivery, state/output/cursor/provenance linkage and retained-checkpoint recovery | Not run |
| Primitive adapters | Occupied/below-floor archive puts; local feedback vs custody; resolver cancellation; collector invalid-first-response slot and distinct validated signatures | Not run |

See [proposal freeze](../e2e/leader.md#planning-completion-versus-proposal-freeze) and the [native recovery owner](../consensus/README.md#native-actors-and-source-layout) for leader/view/context changes. Old reports and advisory work cannot enter a new context; preserve authenticated interpretation and emitted canonical prefixes. Adoption, continuation, and recovery bridges still need implementation and proofs.

With missed direction, the [non-leader path](../e2e/reschedule.md#non-leader-lifecycle-direction-and-branch-execution) continues local intended work and canonical commit. Distinguish late builds through [native request correlation](../consensus/block-body.md#select-transactions-and-build-a-block) and late execution through [generation and access fencing](../execution/qmdb.md#manage-the-branch-tree-for-execution-requests). Neither direction receipt nor canceled-worker completion adds a cut barrier.
