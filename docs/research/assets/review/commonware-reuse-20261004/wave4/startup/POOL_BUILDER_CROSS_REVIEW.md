## Decisive checks

### Public APIs and actual ingress

- Nunchi's crate publicly exports `Mempool`, `MempoolHandle`, `PoolTransaction`, config/status/error types, while `mod pool` remains private. Internal `Pool::finalize`/nonce helpers therefore cannot be called by an unchanged external wrapper just because their method declarations say pub. [Crate boundary](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/lib.rs#L15).
- `submit` awaits the actor's admission responder but has no Source argument. In `start_p2p`, local Submit/SubmitMany routes through `handle_with_gossip`; successful entries send once to `Recipients::All`. The network receive path calls raw `T::read_cfg`, stateless checking and `admit_verified` directly, without that local gossip path or application Features/Decision. Thus external TxPool wrapper methods do not automatically intercept peer admissions. The report correctly leaves policy at admission versus packing undecided and avoids a second candidate queue. [Public submit](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/actor.rs#L64), [local gossip](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/actor.rs#L433), [direct network admission](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/actor.rs#L473).
- Constantinople `try_ingest` is **pub(super)** and resolves actor ingestion, while public `try_submit` resolves eventual batch TxStatus. Exposing/reusing the former requires a narrow source integration; awaiting the latter is not admission completion. [Mailbox boundary](https://github.com/commonwarexyz/constantinople/blob/3b6c92e76bf582855615844a4175b8304808f6a9/crates/mempool/src/webserver/mailbox.rs#L112).

### on_commit completion and canonical refresh

Nunchi `finalized` is a lossy try_send with no responder. Only actor Message::Finalized processing calls Pool::finalize. The report's “When processed” qualification is essential: the public call does not prove cleanup, canonical nonce initialization or selection readiness. Pool::finalize changes only supplied/touched nonce lanes; later lane-B-only processing cannot repair a dropped lane-A update. Unknown lane nonce starts at zero and all these snapshots/statuses are in memory. [Public notification](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/actor.rs#L195), [processing](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/actor.rs#L414), [nonce refresh](https://github.com/nunchi-labs/sdk/blob/eea35ced709f68c15d6fbc8bcc754696a7e44374/mempool/src/pool.rs#L211).

The proposed alternatives correctly distinguish owner-retained reconciliation work from processed backend completion. They are integration choices, not an already supplied public ACK API. Any selected on_commit success meaning must be explicit in application prose; an unreliable notification cannot silently supply the stronger meaning. Linked durable Executor outcomes, including applicable imports, remain the source of cleanup. No pool completion substitutes for Orderer's durable delivery ACK or gates native cut/direction.

### Reth selection and maintenance reuse

- Public `BestTransactions::no_updates` stops pending updates for that iterator. Concrete BestTransactions removes its receiver; it does not freeze provider state or bind a native producer context. `mark_invalid` records an iterator-local invalid sender/dependency exclusion; it does not delete from the backend pool. The report correctly recommends the existing dependency iterator over a new generic selector. [Public iterator contract](https://github.com/paradigmxyz/reth/blob/038edab20dfff017f7a7502e683c732e5628ad89/crates/transaction-pool/src/traits.rs#L1109), [actual no_updates](https://github.com/paradigmxyz/reth/blob/038edab20dfff017f7a7502e683c732e5628ad89/crates/transaction-pool/src/pool/best.rs#L283).
- Reth exposes maintain as a public module and both maintenance entry points. Their actual Client/Pool/notification bounds require the compatible Ethereum-shaped provider graph. Existing maintenance initializes tip when available, reloads dirty accounts, detects first-event/discontinuous/deep drift and processes canonical state updates; mined pruning alone is not that surface. Event stream termination ends it and reloads are asynchronous, so the report correctly avoids unconditional dropped-event/crash guarantees. [Module visibility](https://github.com/paradigmxyz/reth/blob/038edab20dfff017f7a7502e683c732e5628ad89/crates/transaction-pool/src/lib.rs#L324), [maintenance bounds](https://github.com/paradigmxyz/reth/blob/038edab20dfff017f7a7502e683c732e5628ad89/crates/transaction-pool/src/maintain.rs#L98), [event handling](https://github.com/paradigmxyz/reth/blob/038edab20dfff017f7a7502e683c732e5628ad89/crates/transaction-pool/src/maintain.rs#L260).
- Public local backup loads/reinserts at boot and saves after a configured graceful shutdown signal. It supplies no per-admission WAL/crash durability. The report's candidate reuse wording and separate durability limitation are accurate. [Backup task](https://github.com/paradigmxyz/reth/blob/038edab20dfff017f7a7502e683c732e5628ad89/crates/transaction-pool/src/maintain.rs#L828).

## Producer and interface preservation

Nunchi selection clones nonce-contiguous entries and updates its round-robin cursor without popping them. Complete body byte packing/filtering must preserve selected dependency order, bound refills and bind the exact cloned bytes; a later replacement cannot change an already selected body. Several producers can include the same locally deduplicated transaction. No pool operation defines canonical duplicate/replay outcomes. The report preserves those distinctions and native producer parent versus canonical execution state.

Native callback/context facts agree with independently fresh wave-four startup sources for voter/executor.rs and prior pinned callback/body receipts. This review does not convert a source-pinned body recipe into compiled integration. The five public traits and existing Automaton/Relay body surface remain intact; no extra public builder, result-service gate or enforced proposal root is introduced. Suggested Batch/completion prose clarifies associated-type semantics without selecting an implementation.

This review does not certify dependency interchangeability, runtime performance, native protocol execution, publication or six-hour completion. Full startup report review is separate.
