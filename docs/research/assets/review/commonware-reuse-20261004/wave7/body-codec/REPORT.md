## Finding and genuinely new reader delta

**Implement the body representation's existing codec and digest interfaces directly.** No Simplex Block/CertifiableBlock/Application, duplicate native header codec/hash, public body trait, or new generic serialization/cache/parent-lookup service is required. Commonware already supplies ordered Vec/Bytes length encoding and bounded readers, whole-frame decode, encode-size allocation, hash helpers, native header construction/identity and body transport/storage handles.

The existing body page accurately records header→commitment→bytes joining, parent custody, callback lifetime, Archive/resolver ownership and native/protocol caveats. Do not repeat those as a new section. A small addition is useful: name the minimum direct trait implementations, their blanket conveniences, configurable body read bounds, and stable digest invariant. The remaining application work is the chosen body representation and exact join/admissibility/custody checks. READER_DELTA.md proposes only that small table/paragraph in the existing body page.

### Bounds do not require a unit body decoder

Buffered Config explicitly accepts M::Cfg, and concrete Archive init accepts V::Cfg. Generic resolver's wire/key codec uses () because it carries a Span key or Bytes response; Consumer applies the **body** decoder/config to that returned value. Unit wire decode does not force body Read<Cfg=()>. A concrete selected upstream service may require a unit type at its own boundary (e.g. DB operation adapter), but that unrelated bound must not spread into this body attachment. Alto already passes a non-unit body RangeCfg into buffer/storage configuration. [Buffer config](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/broadcast/src/buffered/config.rs#L5), [resolver outer wire](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/resolver/src/p2p/wire.rs#L38), [Alto actual config](https://github.com/commonwarexyz/alto/blob/1d87569348b5560699465a72d691d90f18affb9c/chain/src/engine.rs#L177).

Reuse RangeCfg for counts and each nested variable length; do not introduce another length-prefix codec. Bytes checks advertised length against remaining input before copying. Generic Vec element decoding initially allocates at most min(count,remaining bytes), but zero/small-byte element schemas can still consume work/memory across repeated elements; the explicit chosen count bound remains necessary. Codec does not supply an aggregate application byte/work policy. Validate complete encoded body and resolver framing against the selected transport envelope, as the existing networking/body pages already require. No numeric limits are adopted. [usize length read](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/codec/src/types/primitives.rs#L177), [default element read](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/codec/src/codec.rs#L233).

## Stable content commitment versus native header identity

Commonware supplies hash machinery, not the body commitment rule. For a selected canonical body encoding, existing Encode bytes and Hasher::hash can compute the commitment without another hashing framework. Use the same selected representation and order for construction, decoding, storage and retransmission, and recompute/check untrusted received content. Do not trust a wire-supplied digest or reuse a cached digest after its committed fields change. If a cached encoded body/digest is retained, keep it coherent with stable committed fields under the existing body owner. `Codec` alone does not prove that a custom schema has a unique canonical encoding or full-body binding.

Upstream varint rejects redundant terminal zero and overflow encodings, so the existing vector/byte length prefixes already have a unique accepted encoding. That useful primitive rule does not settle transaction application encoding, field order, domains, schema versions or semantic header commitment checks. These remain selected-format responsibilities. [Unique varint](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/codec/src/varint.rs#L118).

Native Header::new, its Read/Write/EncodeSize and digest::<H>/block_ref::<H> are already public. Header digest hashes its complete existing encoding: epoch, chain, height, **parent header digest**, external body commitment. Body commitment, native header identity, and signed-artifact ArtifactId therefore remain distinct. The application need not create another producer-header codec or protocol-header hash. Context is reconstructed from Header; it is metadata, not a full-body Codec implementation. [Context and header](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/types/block.rs#L47), [header hash](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/types/block.rs#L175), [header codec](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/types/block.rs#L203), [artifact identity](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/machine/admission.rs#L145).

If the transmitted cache object includes extra context/header fields, its digest must uniquely identify that object, or those fields must remain joined separately; one body digest cannot distinguish several different cached envelopes with excluded metadata. Native permits distinct headers to commit the same opaque body. Preserve the current header→body join instead of assuming one cache digest authenticates producer position, parent or signature. This is a type/identity invariant, not a selected envelope schema.

`commonware_consensus::Block` requires a single canonical digest committing the full block including height/parent, and parent() refers to that same block-identity namespace. CertifiableBlock additionally binds its consensus context. Those contracts support the Simplex examples; they are **not** required for a native body whose parent is a separate native header reference. Do not copy these traits merely to gain Codec or Digestible. [Block contract](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/lib.rs#L56).

## Missing parent and custody: existing documentation is already adequate

Decoding a bounded body and matching its commitment cannot establish required parent custody. Context::parent identifies the producer parent header, which must resolve through the existing authenticated header record to its body commitment and retained bytes. Synthetic genesis follows the actual native genesis rules; arbitrary missing parents must not be substituted with an empty body or false verdict. The existing body page already preserves pending request semantics and exact durable custody before success, with permanent invalidity distinct from a bad peer response.

Native recovery derives `(Context::from(header), header.commitment())` for its recovered local authority and requires application reverification. Native headers and valid native signatures do not reconstruct external bodies or provide their durable custody. Reuse the existing archive/buffer/resolver and the same narrow attachment; no new generic parent decoder/database is implied. [Native recovered requirements](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/multimmit/machine/chain.rs#L1618), [Automaton request semantics](https://github.com/commonwarexyz/monorepo/blob/534af0ede48affd35b2111522527547b4cc9bf72/consensus/src/lib.rs#L116).

No custody quorum, full-body ACK, protocol bridge or concrete retention policy follows from this audit. Keep cut/report/direction no-wait, five public application traits, Executor/Storage separation and unresolved native prefix-preservation proofs unchanged.
